The short version: in a context that supports tidy-eval injection, !! embeds a value or a captured expression into code that is about to run. Prefer {{ }} for ordinary argument forwarding, and .data[[name]] or all_of(name) for character column names.

The one-sentence mental model

!! is read “bang-bang” and has traditionally been called unquote. The useful idea is not the name but when it changes the code:

In a context that supports tidy-eval injection, evaluate the object on the right of !!, embed its value or expression into the surrounding expression, and only then evaluate the modified outer expression.

For example, save a piece of code and inject it into filter():

library(dplyr)
library(rlang)

rule <- expr(age > 25)

df |>
  filter(!!rule)

The conceptual sequence is:

rule                     # an env-variable containing the expression age > 25
  ↓  !!rule
age > 25                 # code injected into filter()
  ↓
filter(df, age > 25)     # the modified call is evaluated

!! is not a column-name operator, and it does not itself extract a value from a data frame. It injects an R object. That object can be a symbol, call, quosure, constant, or dynamically generated name.

1. Why dplyr programming needs indirection

1.1 Data-variables and env-variables

Functions such as filter(), mutate(), summarise(), and group_by() use data masking. Data masking lets you refer to columns directly:

df <- tibble(
  name  = c("Tom", "Jack", "Amy"),
  age   = c(20, 35, 28),
  score = c(80, 95, 88)
)

df |>
  filter(age > 25)

Two kinds of “variable” are visible:

Kind Where it lives Examples Explicit form
data-variable A data-frame column age, score .data$age
env-variable The current R environment cutoff <- 25 .env$cutoff

Direct column names are convenient during interactive analysis. A wrapper function introduces indirection: the desired column is now supplied through a function argument.

1.2 Why a naive wrapper fails

The argument named variable is not an automatic placeholder for a column:

bad_filter <- function(data, variable) {
  data |>
    filter(variable > 25)
}

# bad_filter(df, age)
# Typically errors because object age is not found.

filter() first looks for a column literally named variable. If none exists, it looks in the function environment and finds the argument promise. Forcing that promise tries to evaluate age as an ordinary object in the caller, where it usually does not exist.

What we need is: “Capture what the caller wrote without immediately evaluating it as an ordinary argument, then arrange for that expression to be evaluated inside filter()’s data mask.” This is the defuse-and-inject pattern.

2. The classic pattern: enquo() + !!

2.1 The two separate operations

my_filter <- function(data, variable, cutoff = 25) {
  variable <- enquo(variable)          # 1. Capture expression and environment.

  data |>
    filter(!!variable > .env$cutoff)   # 2. Inject the expression.
}

my_filter(df, age)
my_filter(df, score, cutoff = 85)

When my_filter(df, age) runs:

  1. enquo(variable) captures the caller’s expression age as a quosure.
  2. A quosure stores both an expression and an associated environment.
  3. !!variable injects the captured object into filter().
  4. The modified condition has the shape age > .env$cutoff and is evaluated in the data mask.

Writing .env$cutoff is deliberate. If the input data also contains a column named cutoff, the function still uses its parameter.

2.2 Expressions, symbols, calls, and quosures

Several object types matter:

Object How to create it What it stores Carries an environment?
symbol sym(“age”) The name age No
call/expression expr(age > 25) A syntax tree No
quosure quo(age > x) or enquo(arg) An expression Yes
ordinary value 25, a string, a vector Data Not applicable

!! can inject all of these, but the resulting evaluation semantics depend on the object and its context. A quosure is normally the right capture type for a user argument because the expression may refer to values in the caller’s environment.

2.3 Inspecting the result of injection

rlang::qq_show() is useful when learning or debugging quasiquotation:

variable <- quo(age)
cutoff <- 25

qq_show(
  dplyr::filter(df, !!variable > !!cutoff)
)

It shows the shape of the expression after injection. You do not need it in production code, but it helps answer the question, “Am I holding data, a symbol, or code?”

3. Using !! with common dplyr verbs

The following examples intentionally use the classic enquo() + !! pattern to expose the mechanism. Section 9 rewrites ordinary single-argument forwarding with {{ }}.

3.1 summarise(): choose a variable dynamically

get_mean_old <- function(data, variable) {
  variable <- enquo(variable)

  data |>
    summarise(avg = mean(!!variable, na.rm = TRUE))
}

get_mean_old(df, score)
get_mean_old(df, age)

The first call places mean(score, na.rm = TRUE) into summarise().

3.2 group_by(): choose grouping dynamically

patients <- tibble(
  hospital = c("FMC", "FMC", "RGH", "RGH"),
  sex      = c("M", "F", "M", "F"),
  age      = c(65, 72, 58, 81)
)

summary_by_old <- function(data, group_var) {
  group_var <- enquo(group_var)

  data |>
    group_by(!!group_var) |>
    summarise(
      mean_age = mean(age),
      n = n(),
      .groups = "drop"
    )
}

summary_by_old(patients, hospital)
summary_by_old(patients, sex)

3.3 arrange(): dynamic sorting

sort_desc_old <- function(data, variable) {
  variable <- enquo(variable)

  data |>
    arrange(desc(!!variable))
}

sort_desc_old(df, score)

Injection occurs inside desc(), so the resulting code has the shape arrange(desc(score)).

3.4 mutate(): use an expression in a calculation

add_double_old <- function(data, variable) {
  variable <- enquo(variable)

  data |>
    mutate(double = !!variable * 2)
}

add_double_old(df, score)

Read !!variable * 2 as “put the captured expression on the left side of this multiplication call,” not as a special form of column extraction.

3.5 Reusing one captured expression

Explicit capture still matters in advanced functions because a quosure can be stored, inspected, transformed, or injected multiple times:

standardise <- function(data, variable) {
  variable <- enquo(variable)

  data |>
    mutate(
      centered = !!variable - mean(!!variable, na.rm = TRUE),
      scaled = centered / sd(!!variable, na.rm = TRUE)
    )
}

standardise(df, score)

4. Character column names: do not automatically reach for !!sym()

4.1 Use .data[[name]] in data-masked calculations

If a column name is already a string, the clearest interface is usually:

mean_from_string <- function(data, variable) {
  data |>
    summarise(avg = mean(.data[[variable]], na.rm = TRUE))
}

mean_from_string(df, "score")

.data[[variable]] states that variable is an env-variable containing a string with which to index the data. The name inside [[ ]] is never confused with a data column.

Filtering and sorting use the same pattern:

filter_from_string <- function(data, variable, cutoff) {
  data |>
    filter(.data[[variable]] > .env$cutoff)
}

arrange_from_string <- function(data, variable) {
  data |>
    arrange(.data[[variable]])
}

4.2 Use all_of() in tidy selection

select(), rename(), relocate(), and the selection part of across() use tidy-selection semantics. Prefer all_of() for strings or character vectors:

keep_columns <- function(data, variables) {
  data |>
    select(all_of(variables))
}

keep_columns(df, c("name", "score"))

Use any_of() only when the interface is intentionally allowed to ignore missing columns. Its error policy differs from all_of().

4.3 What !!sym() still means

Older code often uses:

variable <- "age"

df |>
  filter(!!sym(variable) > 25)

The operations are:

"age" → sym("age") → symbol age → !! injection → filter(age > 25)

This symbolise-and-inject pattern is still valid, especially when genuinely constructing expressions. For simply reading one column by a string, .data[[variable]] is more direct. In a tidy-selection argument, all_of(variable) communicates the intent better.

5. Injecting a complete expression

5.1 Save and inject a rule

rule <- expr(age > 25 & score > 85)

df |>
  filter(!!rule)

This is the representative use of !!: it is an expression-injection tool, not merely column-name interpolation. Rules can be created, stored, logged, combined, and eventually evaluated by a data-masking verb.

5.2 Build a rule from a string and a value

make_threshold_rule <- function(column, cutoff) {
  column <- sym(column)
  expr(!!column >= !!cutoff)
}

rule <- make_threshold_rule("score", 88)
rule

df |>
  filter(!!rule)

Inside expr():

  • The first !! injects the symbol score.
  • The second injects the constant 88.
  • The returned object is the expression score >= 88; it has not yet been evaluated against any data.

5.3 A quosure preserves the user’s environment

make_filter <- function(data, condition) {
  condition <- enquo(condition)
  data |> filter(!!condition)
}

limit <- 85
make_filter(df, score > limit)

The user’s expression refers both to the data column score and to limit in the caller’s environment. The quosure captured by enquo() retains that environment so limit can be resolved correctly after injection.

6. Injecting ordinary values and resolving ambiguity

A data column masks an env-variable with the same name:

example <- tibble(
  score = c(80, 90),
  cutoff = c(100, 100)
)

cutoff <- 85

example |>
  filter(score > cutoff)       # cutoff refers to the data column.

In production code, .env is usually the clearest disambiguation:

example |>
  filter(score > .env$cutoff)

You can also inject the already determined value:

example |>
  filter(score > !!cutoff)

Both avoid masking by the data column. Prefer .env$cutoff for a straightforward environment value; value injection is natural when constructing code that will be stored or transformed further.

7. Dynamic output names: !!name :=

A regular equals sign cannot substitute an env-variable on its left side. Dynamic names use :=:

new_name <- "mean_age"

patients |>
  summarise(
    !!new_name := mean(age)
  )

The resulting column is named mean_age, not new_name.

7.1 A dynamic input expression and output name

summary_function <- function(data, variable, output_name) {
  variable <- enquo(variable)

  data |>
    summarise(
      !!output_name := mean(!!variable, na.rm = TRUE)
    )
}

summary_function(
  patients,
  age,
  "average_patient_age"
)

The left side injects a name string; the right side injects the captured column expression. Both use !!, but they occupy different syntactic roles.

7.2 Modern name interpolation

Dynamic dots also support glue-style names:

summary_function_modern <- function(data, variable, output_name) {
  data |>
    summarise(
      "{output_name}" := mean({{ variable }}, na.rm = TRUE)
    )
}

This is especially readable when composing a name, such as “mean_{suffix}” := …. Explicit !!name := remains useful when a symbol or call is part of more involved code generation.

8. !! versus !!!: inject one, splice many

!! injects one object. !!! splices the elements of a list into a call as multiple arguments.

8.1 Multiple filtering conditions

rules <- exprs(
  age > 25,
  score > 85
)

df |>
  filter(!!!rules)

The expanded call conceptually becomes:

df |>
  filter(
    age > 25,
    score > 85
  )

filter() combines its conditions with AND. That behavior belongs to filter(), not to !!!; splicing only creates multiple arguments.

8.2 Generate multiple summaries

summaries <- list(
  mean_score = expr(mean(score, na.rm = TRUE)),
  max_score  = expr(max(score, na.rm = TRUE))
)

df |>
  summarise(!!!summaries)

The list names become output names and the expressions become the corresponding summary arguments.

8.3 Splicing into an ordinary function call

Use inject() when an ordinary call does not itself provide injection support:

args <- list(na.rm = TRUE, trim = 0.1)
x <- c(1, 2, 3, NA)

inject(mean(x, !!!args))

Injection operators are not a base-R syntax extension that works everywhere. inject() explicitly creates a context that understands them.

9. The modern default: when to use {{ }}

For the common task “the user supplies one unquoted expression and I simply forward it to a data-masking or tidy-selection argument,” prefer {{ }}.

get_mean <- function(data, variable) {
  data |>
    summarise(avg = mean({{ variable }}, na.rm = TRUE))
}

get_mean(df, score)

In this direct-forwarding case, you can conceptually simplify:

variable <- enquo(variable)
summarise(data, avg = mean(!!variable, na.rm = TRUE))

to:

summarise(data, avg = mean({{ variable }}, na.rm = TRUE))

{{ variable }} is called embracing. It combines capture and injection, but it does not make explicit !! obsolete.

9.1 When explicit enquo() + !! still helps

Explicit capture is appropriate when you need to:

  • store a quosure for later evaluation or pass it elsewhere;
  • inspect, label, validate, or transform a user expression;
  • inject the same expression into several dynamically generated calls;
  • build larger syntax trees with expr(), call2(), or related tools;
  • implement a low-level tidy-eval API rather than merely forward one argument.

9.2 Modern versions of common wrappers

summary_by <- function(data, group_var) {
  data |>
    group_by({{ group_var }}) |>
    summarise(mean_age = mean(age), .groups = "drop")
}

sort_desc <- function(data, variable) {
  data |>
    arrange(desc({{ variable }}))
}

add_double <- function(data, variable) {
  data |>
    mutate(double = {{ variable }} * 2)
}

select_columns <- function(data, variables) {
  data |>
    select({{ variables }})
}

The last wrapper accepts a tidy-select expression such as starts_with(“lab_”) or c(age, score). If its interface accepts a character vector instead, use all_of(variables).

10. Where !! works

!! works only in special contexts that understand injection. Typical examples include:

  • tidyverse data-masking arguments powered by tidy evaluation;
  • dynamic dots;
  • injection-aware quoting functions such as rlang::expr() and quo();
  • a context created explicitly by rlang::inject().

In an ordinary base-R expression, the parser sees two logical negations:

!!10
# Same as !(!10), producing TRUE.

!!0
# Produces FALSE.

The following is therefore not a universal form of unquote:

x <- 10
x + !!2
# In ordinary R this is x + TRUE, not metaprogramming injection.

The dangerous part is that misuse may silently produce a logical value instead of throwing an error. Whenever you see !!, ask: “Does the outer function explicitly support tidy-eval injection?”

11. Common misconceptions and corrections

Misconception 1: !! is only for inserting column names

Correction: it injects objects and expressions. A column-name symbol is just one possible object.

Misconception 2: every character column name should become !!sym(name)

Correction: prefer .data[[name]] for data-masked computations and all_of(name) for tidy selection. Use symbolise-and-inject when you genuinely need to construct code.

Misconception 3: every function argument needs enquo() + !!

Correction: ordinary values follow ordinary R evaluation. Simple forwarding of a data-masked expression normally uses {{ }}. Character-name interfaces use .data or all_of().

Misconception 4: !! immediately calculates its right side in the data

Correction: it first modifies the outer code. Evaluation against the data occurs when the modified call runs.

Misconception 5: !!! is merely “more bang-bang”

Correction: !! puts one object into one syntactic position. !!! splices multiple objects into multiple argument positions. The outer context controls whether splicing is allowed and how names are handled.

Misconception 6: names in a data mask cannot collide

Correction: a data column normally takes precedence over an env-variable. Use .data$column, .data[[name]], and .env$value to state the source explicitly in production code.

12. Practical decision table

Input you have Calling form Preferred tool Typical code
User-supplied bare column/expression f(data, age) {{ arg }} mean({{ arg }})
String column name for calculation name <- “age” .data[[name]] mean(.data[[name]])
Character vector for selection vars <- c(“age”,“score”) all_of(vars) select(all_of(vars))
Character vector for permissive selection Some columns may be absent any_of(vars) select(any_of(vars))
Captured quosure q <- enquo(arg) !!q filter(!!q)
Constructed expression rule <- expr(…) !!rule filter(!!rule)
Several expressions/arguments rules <- exprs(…) !!!rules filter(!!!rules)
Explicit injection context required The ordinary call does not support injection inject() inject(f(!!x))
The function itself is dynamic A variable contains a function or its name exec() exec(fun, !!!args)
Base R call from an argument list Arguments are stored in an ordinary list do.call() do.call(fun, args)
Ordinary environment value cutoff <- 25 .env$cutoff filter(age > .env$cutoff)
Dynamic output name name <- “avg” := plus injection/interpolation !!name := value

A reliable decision process is:

  1. Inspect the target parameter’s documentation: is it ordinary, <data-masking>, <tidy-select>, or dynamic dots?
  2. Decide whether the caller provides a bare expression, string, ordinary value, captured expression, or list of expressions.
  3. Choose the most direct tool that makes the interface contract visible. Do not use !! merely because it is available.

13. Modern alternatives and related call tools

!! is only one form of injection in tidy evaluation. Everyday dplyr programming more often uses {{ }}, .data[[ ]], and all_of(). Explicit !!, !!!, inject(), and exec() become central when you dynamically generate expressions, rules, or entire function calls.

13.1 {{ }}: the modern default for forwarding

The classic form captures and then injects:

my_mean_old <- function(data, var) {
  var <- enquo(var)

  data |>
    summarise(avg = mean(!!var, na.rm = TRUE))
}

The modern form embraces the function argument directly:

my_mean <- function(data, var) {
  data |>
    summarise(avg = mean({{ var }}, na.rm = TRUE))
}

my_filter <- function(data, var) {
  data |>
    filter({{ var }} > 10)
}

my_mean(df, score)
my_filter(df, age)

For this capture-once-and-forward pattern:

enquo(var) + !!var  →  {{ var }}

This should be the first pattern you learn for ordinary dplyr wrappers. Return to explicit enquo() + !! when you must store, inspect, transform, or delay the quosure.

13.2 .data[[ ]]: character column names in calculations

If the caller supplies “age” rather than the bare name age, design an ordinary string interface:

my_filter_string <- function(data, var) {
  data |>
    filter(.data[[var]] > 10)
}

my_filter_string(df, "age")

This is normally more direct than symbolising and injecting:

var <- "age"

# Valid, but indirect when all you need is a column named by a string.
df |>
  filter(!!sym(var) > 10)

# Preferred.
df |>
  filter(.data[[var]] > 10)

A useful shorthand is:

String used in a data-masked calculation:
!!sym(var)  →  .data[[var]]

13.3 all_of(): character names in select()

When a character vector enters a tidy-selection argument, use all_of():

vars <- c("age", "score")

df |>
  select(all_of(vars))

var <- "age"

df |>
  select(all_of(var))

Compare it with the older symbolise-and-splice pattern:

# No need to turn each string into a symbol and splice the result.
df |> select(!!!syms(vars))

# Clearly states that vars is an external character vector.
df |> select(all_of(vars))

all_of() also preserves the order in the character vector and throws an error when any requested name is absent, making it appropriate for workflows with a required schema.

13.4 any_of(): allow columns to be absent

any_of() takes the same input as all_of() but uses a permissive missing-column policy:

vars <- c("age", "score", "hospital")

# all_of() errors if hospital is absent.
# df |>
#   select(all_of(vars))

# any_of() selects only columns that actually exist.
df |>
  select(any_of(vars))

This is particularly useful with healthcare data from different years, institutions, or sources, where optional fields often differ. Make the contract explicit:

  • Require every column: all_of().
  • Select whichever columns exist: any_of().
  • Remove columns idempotently: select(-any_of(vars)).

13.5 inject(): explicitly create an injection context

inject() immediately evaluates an expression with support for !! and !!!:

library(rlang)

var <- sym("age")

inject(
  filter(df, !!var > 10)
)

Because filter() already supports tidy-eval injection, the outer inject() only makes the process explicit; it is not required. A base call that does not itself understand injection is a more representative example:

var <- sym("age")

inject(
  with(df, !!var > 10)
)

It can also splice an argument list into an ordinary function call:

args <- list(
  na.rm = TRUE,
  trim = 0.1
)
x <- c(1, 2, NA, 4)

inject(
  mean(x, !!!args)
)

Think of inject() as: “Interpret injection operators here, then run the modified call.” Routine dplyr analysis rarely needs the extra wrapper.

13.6 exec(): when the function itself is dynamic

exec() constructs and evaluates a call to .fn. The function can be a function object or a string:

args <- list(
  x = c(1, 2, NA, 4),
  na.rm = TRUE
)

exec(mean, !!!args)

fun <- "mean"
x <- c(1, 2, NA, 4)

exec(
  fun,
  x,
  na.rm = TRUE
)

The distinction is important: exec() does not automatically unpack a list. When arguments are stored in a list, continue to write !!!args:

# Correct: splice list elements into separate arguments of mean().
exec(mean, !!!args)

# Usually not intended: pass the whole list as one argument to mean().
exec(mean, args)

Its benefit is “dynamic function plus dynamic dots,” not the elimination of !!!. It also combines naturally with lapply() or purrr::map() when calling a collection of functions.

13.7 Base R do.call(): no tidy evaluation required

Base R’s do.call() accepts a function and an ordinary argument list:

args <- list(
  x = c(1, 2, NA, 4),
  na.rm = TRUE
)

do.call(mean, args)

Conceptually, this is equivalent to:

mean(
  x = c(1, 2, NA, 4),
  na.rm = TRUE
)

For “expand an argument list into a call,” exec(fun, !!!args) and do.call(fun, args) have similar goals, but their evaluation details are not identical—especially when the list contains expression objects. Either is clear for ordinary value arguments; do.call() is the natural Base R solution when tidy evaluation is not otherwise needed.

13.8 Classify the input first

User supplies a bare column name: age
  → {{ var }}

User supplies a string for calculation: "age"
  → .data[[var]]

Character vector used in select()
  → all_of(vars) / any_of(vars)

One captured or constructed expression
  → !!expression

Several expressions or dynamic-dot arguments
  → !!!expressions

An explicit injection context is required
  → inject(...)

The function itself is dynamic
  → exec(fun, !!!args)

Base R call from an argument list
  → do.call(fun, args)

Do not reach for !! whenever you see a dynamic variable. The most common tools in modern dplyr wrappers are {{ var }}, .data[[var]], and all_of(vars). Explicit !! and !!! matter most for generated expressions, complex rules, and metaprogramming.

14. Worked example: a reusable grouped summary

This function combines modern forwarding, character-vector selection, and dynamic names:

grouped_summary <- function(data, group, value_names, prefix = "mean") {
  data |>
    group_by({{ group }}) |>
    summarise(
      across(
        all_of(value_names),
        ~ mean(.x, na.rm = TRUE),
        .names = paste0(prefix, "_{.col}")
      ),
      .groups = "drop"
    )
}

clinical <- tibble(
  site = c("A", "A", "B", "B"),
  age = c(60, 72, 58, 81),
  systolic = c(130, 142, 125, 150)
)

grouped_summary(
  clinical,
  site,
  c("age", "systolic"),
  prefix = "avg"
)

The example contains no explicit !!. That is the point: mastery of tidy evaluation means choosing correctly among {{ }}, all_of(), .data, .env, !!, and !!!, not adding bang-bang everywhere.

Bring !! back when the rule itself is constructed at runtime:

filter_with_rule <- function(data, rule) {
  data |>
    filter(!!rule)
}

rule <- expr(age >= 65 | systolic >= 140)
filter_with_rule(clinical, rule)

15. Exercises and solutions

Exercises

  1. Write a function that accepts a bare column name and returns its median.
