How to use this guide

Antonio Gasparrini’s 2011 paper, Distributed Lag Linear and Non-Linear Models in R: The Package dlnm, introduced a practical framework for relationships that may be non-linear in exposure and delayed across time. This guide explains that framework, reconstructs its key example with the current package interface, and then extends the workflow through prediction, reduction, diagnostics, missing data, and penalized models.

Read Chapters 1–5 for the concepts, Chapters 6–10 for a complete analysis, and Chapters 11–15 before adapting the code to research data. The examples estimate associations; they do not, by themselves, establish causality.

1. Why distributed lag models?

An exposure observed today may affect an outcome today, tomorrow, or weeks later. Temperature can have acute heat effects and longer cold effects; air pollution may have effects spread over several days. A conventional regression containing only today’s exposure imposes lag 0. Adding one coefficient per lag is flexible but often unstable because adjacent lagged exposures are highly correlated.

A distributed lag model constrains the lag pattern to a lower-dimensional function. A distributed lag non-linear model adds a second flexible function for the exposure-response shape.

Three model classes

Model Exposure-response Lag-response Typical question
Single-lag regression Usually linear or spline One selected lag What is the association at lag 2?
DLM Linear Flexible How is the effect of a fixed exposure increment distributed across lags?
DLNM Flexible Flexible How do both exposure level and delay shape the association?

In compact form, a time-series DLNM contributes this term to the linear predictor:

sum over lag l = 0,...,L of  f(exposure at time t-l, lag l)

The regression model supplies the outcome family, link, confounders, and uncertainty calculation. The cross-basis supplies f(), the two-dimensional exposure-lag-response surface.

2. The cross-basis idea

crossbasis() constructs basis functions in two spaces and combines them:

  1. Predictor space: how risk changes as exposure changes.
  2. Lag space: how an exposure’s association changes as time since exposure increases.

If the predictor basis has p columns and the lag basis has q columns, the cross-basis usually contributes p * q columns. Regression estimates one coefficient for each combined basis column. crosspred() then maps those coefficients back to interpretable contrasts on an exposure-by-lag grid.

Basis choices

fun Meaning Good use
"lin" Linear term A DLM or a scientifically justified linear dimension.
"ns" Natural cubic spline Smooth, stable curves with linear tails.
"bs" B-spline Flexible piecewise-polynomial curves with explicit degree/df control.
"thr" High, low, or double threshold A piecewise-linear effect beyond selected thresholds.
"strata" Piecewise-constant intervals Interpretable lag blocks or exposure categories.
"integer" One indicator per integer Unconstrained lag coefficients for a short lag range.
"poly" Polynomial basis Compact curves, but potentially fragile at boundaries.
"ps", "cr" Penalized splines Advanced models where smoothness is estimated.

Use a simple, scientifically defensible specification first. Increasing flexibility in both dimensions multiplies the number of parameters and can create a visually impressive but unstable surface.

Intercepts and identifiability

Do not include an intercept in argvar. The regression already has an intercept; an intercept in predictor space commonly creates collinearity and rank deficiency. An intercept in the lag basis is included by default and is normally appropriate.

cb <- crossbasis(
  x,
  lag = 21,
  argvar = list(fun = "ns", df = 4, intercept = FALSE),
  arglag = list(fun = "ns", df = 4)
)

summary(cb)
qr(cb[complete.cases(cb), ])$rank
ncol(cb)

If rank is smaller than the number of columns, simplify the basis before fitting. Prediction and reduction can fail when the regression silently drops collinear columns.

3. The current dlnm workflow

The reusable workflow has six steps:

  1. Preserve a complete, correctly ordered time index.
  2. Choose a lag window and two marginal basis functions.
  3. Build a cross-basis with crossbasis().
  4. Include that object in a supported regression model.
  5. Generate contrasts with crosspred() and an explicit reference value.
  6. Visualize or reduce the fitted surface with plot() and crossreduce().
library(dlnm)
library(splines)

cb <- crossbasis(
  data$exposure,
  lag = 21,
  argvar = list(fun = "ns", df = 4),
  arglag = list(fun = "ns", df = 4)
)

fit <- glm(
  outcome ~ cb + ns(time, df = 7 * years) + day_of_week,
  family = quasipoisson(),
  data = data
)

pred <- crosspred(cb, fit, cen = reference, by = 1, cumul = TRUE)
plot(pred, "overall")

The exact same object name matters: crosspred() and crossreduce() use the basis object and coefficient names to locate the relevant model terms. Give two cross-bases distinct names when both enter one model.

The package documentation warns that reconstructed pollutant values can be negative. Do not silently truncate them without a scientific and measurement-model justification.

Preserve the calendar

For vector input, crossbasis() assumes an equally spaced, complete, ordered series. Do not run na.omit() on the entire data frame before building the basis: removing a date makes adjacent rows look like adjacent days even when they are not.

stopifnot(!is.unsorted(chicagoNMMAPS$date))
stopifnot(all(diff(chicagoNMMAPS$date) == 1))

Missing exposure values are allowed, but one missing exposure makes the basis row and subsequent rows in its lag window unavailable. Long lag windows can therefore amplify data loss.

5. Choosing a lag window and basis

Start from the scientific time scale

The maximum lag is a scientific assumption before it is a tuning parameter. It should be long enough to capture plausible delayed effects, but not so long that unrelated variation is folded into the exposure term.

  • Acute pollution effects often use a relatively short window.
  • Temperature effects may require several weeks.
  • Long-latency occupational or pharmaceutical settings can use negative or much longer lags when the study design supports them.

Run sensitivity analyses around a defensible primary lag, rather than searching every possible maximum and reporting the most striking curve.

Knots and degrees of freedom

df lets a spline function choose knots automatically. Explicit knots make the model specification easier to reproduce and explain.

lag_knots <- logknots(30, nk = 3)
exposure_knots <- quantile(
  chicagoNMMAPS$temp,
  probs = c(0.10, 0.75, 0.90),
  na.rm = TRUE
)

cb_temp <- crossbasis(
  chicagoNMMAPS$temp,
  lag = 30,
  argvar = list(fun = "ns", knots = exposure_knots),
  arglag = list(fun = "ns", knots = lag_knots)
)

logknots() places more lag knots near lag 0, where associations often change more rapidly. This helper reproduces older log-spaced defaults; current crossbasis() does not apply that old default automatically.

6. Example A — a linear DLM for ozone

This first model keeps the exposure-response linear and lets the lag-response be smooth. It answers: relative to ozone 0, how is the association for a given ozone level distributed across lags 0–10?

cb_o3_linear <- crossbasis(
  chicagoNMMAPS$o3,
  lag = 10,
  argvar = list(fun = "lin"),
  arglag = list(fun = "ns", knots = logknots(10, 3))
)

summary(cb_o3_linear)

Fit a quasi-Poisson time-series regression:

fit_o3_linear <- glm(
  death ~ cb_o3_linear +
    ns(temp, df = 6) +
    ns(time, df = 7 * 14) +
    dow,
  family = quasipoisson(),
  data = chicagoNMMAPS
)

summary(fit_o3_linear)

Here ns(time, 7 * 14) uses seven degrees of freedom per year for long-term and seasonal pattern, and dow adjusts for day of week. The same-day temperature spline keeps this example focused on DLM mechanics; it is not a universal confounding strategy. A real protocol must predefine weather, seasonality, holidays, epidemics, trends, and other context-specific controls.

Generate predictions at explicit ozone values:

pred_o3_linear <- crosspred(
  cb_o3_linear,
  fit_o3_linear,
  at = seq(0, 60, by = 5),
  cen = 0,
  cumul = TRUE
)

plot(
  pred_o3_linear,
  "slices",
  var = 50,
  ci = "lines",
  xlab = "Lag (days)",
  ylab = "Relative risk",
  main = "Lag-response at ozone = 50 versus 0"
)

pred_o3_linear$allRRfit["50"]
cbind(
  low = pred_o3_linear$allRRlow["50"],
  high = pred_o3_linear$allRRhigh["50"]
)

matRRfit contains lag-specific relative risks. allRRfit contains the overall cumulative association across the complete lag interval. cumRRfit is created because cumul = TRUE and traces the incremental cumulative association through lag.

7. Example B — reconstruct the paper’s threshold model

The paper’s ozone example models no linear increase below 40.3 and a linear increase above that threshold, with separate lag coefficients. The current package manual demonstrates this as a seasonal analysis.

Keep summer segments independent

Subsetting to June–September creates a gap between one summer and the next. group = year prevents the cross-basis from carrying a December-to-June lag history across that gap.

chicago_summer <- subset(chicagoNMMAPS, month > 5 & month < 10)

cb_o3_threshold <- crossbasis(
  chicago_summer$o3,
  lag = 5,
  argvar = list(fun = "thr", thr = 40.3),
  arglag = list(fun = "integer"),
  group = chicago_summer$year
)

cb_temp_threshold <- crossbasis(
  chicago_summer$temp,
  lag = 10,
  argvar = list(fun = "thr", thr = c(15, 25)),
  arglag = list(fun = "strata", breaks = c(2, 6)),
  group = chicago_summer$year
)

The ozone predictor basis is a high-threshold function by default when one threshold is supplied. The temperature basis has low and high linear pieces around 15 and 25. The lag bases are deliberately interpretable: one ozone parameter per lag and three temperature lag strata.

fit_paper_style <- glm(
  death ~ cb_o3_threshold + cb_temp_threshold +
    ns(doy, df = 4) + ns(time, df = 3) + dow,
  family = quasipoisson(),
  data = chicago_summer
)

pred_o3_threshold <- crosspred(
  cb_o3_threshold,
  fit_paper_style,
  at = c(0:65, 40.3, 50.3)
)

pred_o3_threshold$allRRfit["50.3"]
cbind(
  low = pred_o3_threshold$allRRlow["50.3"],
  high = pred_o3_threshold$allRRhigh["50.3"]
)[1, ]

In the validation run for this guide, the overall relative risk at 50.3 versus the threshold reference was about 1.0473. Treat that number as a reproducibility check, not a new scientific result.

8. Example C — a non-linear temperature DLNM

Now let both dimensions be non-linear. This follows the spirit of the paper’s 30-day temperature example while using current syntax and moving centering to prediction.

cb_temp_nonlinear <- crossbasis(
  chicagoNMMAPS$temp,
  lag = 30,
  argvar = list(fun = "bs", degree = 3, df = 6),
  arglag = list(fun = "ns", df = 5)
)

summary(cb_temp_nonlinear)

Six predictor-basis columns crossed with five lag-basis columns produce 30 DLNM coefficients. The full regression also estimates the intercept, 98 time-spline coefficients, and day-of-week contrasts.

fit_temp_nonlinear <- glm(
  death ~ cb_temp_nonlinear + ns(time, df = 7 * 14) + dow,
  family = quasipoisson(),
  data = chicagoNMMAPS
)

pred_temp_nonlinear <- crosspred(
  cb_temp_nonlinear,
  fit_temp_nonlinear,
  at = seq(-20, 33, by = 1),
  cen = 25,
  cumul = TRUE
)

Every contrast is relative to 25°C. Centering changes the comparison and presentation, not the fitted coefficients. Select the reference because it is scientifically meaningful and sufficiently supported by the data—not because it makes the graph attractive.

Overall cumulative association

plot(
  pred_temp_nonlinear,
  "overall",
  xlab = "Temperature (°C)",
  ylab = "Overall cumulative relative risk"
)

plot(
  pred_temp_nonlinear,
  "slices",

  cumul = TRUE,
  ci = "lines",
  xlab = "Lag through which effects are accumulated",
  ylab = "Incremental cumulative relative risk"

Do not call a lag-specific RR a cumulative RR. The former is one cell or slice of the surface; the latter sums contributions across a defined lag interval on the linear-predictor scale before exponentiation.

10. Reduce a fitted DLNM with crossreduce()

crossreduce() re-expresses a two-dimensional fit as a lower-dimensional basis with modified coefficients and covariance matrix. It is useful for meta-analysis, compact reporting, and extracting a single scientifically targeted curve.

reduced_overall <- crossreduce(
  cb_temp_nonlinear,
  fit_temp_nonlinear,
  type = "overall",
  cen = 25
)

reduced_lag7 <- crossreduce(
  cb_temp_nonlinear,
  fit_temp_nonlinear,
  type = "lag",
  value = 7,
  cen = 25
)

reduced_at33 <- crossreduce(
  cb_temp_nonlinear,
  fit_temp_nonlinear,
  type = "var",
  value = 33,
  cen = 25
)
Reduction Result
type = "overall" Cumulative exposure-response curve across the lag window.
type = "lag", value = 7 Exposure-response curve at lag 7.
type = "var", value = 33 Lag-response curve at 33°C. 
plot(reduced_overall, xlab = "Temperature", ylab = "Relative risk")
coef(reduced_overall)
vcov(reduced_overall)

Reduction is not a refit and does not repair a poorly specified model. It is a linear transformation of the original fitted coefficients and their covariance.

11. Missing values, gaps, groups, and exposure histories

Missing exposure values propagate forward

With vector input and a maximum lag L, an unavailable exposure at time t affects basis rows that require it, potentially through t + L. Quantify this before fitting:

cb_pm10 <- crossbasis(
  chicagoNMMAPS$pm10,
  lag = 10,
  argvar = list(fun = "lin"),
  arglag = list(fun = "ns", df = 4)
)

sum(is.na(chicagoNMMAPS$pm10))
sum(!complete.cases(cb_pm10))

Do not fix this by deleting dates first. Options include a prespecified imputation model, a justified shorter lag, a complete subperiod that still preserves daily spacing, or a design that explicitly represents exposure histories.

Independent series with group

Use group for several complete, ordered series stacked in one vector—for example, multiple cities or separated seasonal segments. Lag histories reset at each group boundary.

cb_grouped <- crossbasis(
  data$exposure,
  lag = 7,
  argvar = list(fun = "lin"),
  arglag = list(fun = "ns", df = 3),
  group = data$city
)

Rows within each group still need to be consecutive and correctly ordered. group does not repair an irregular calendar.

Matrix input beyond regular time series

x can be a matrix whose rows are subjects or events and whose columns are complete exposure histories over the lag interval. This supports nested case-control, longitudinal, and trial settings.

# Six columns represent lags 0, 1, ..., 5 for each observation.
X_history <- matrix(
  c(
    0, 0, 10, 20, 10, 0,
    0, 5, 15, 15,  5, 0,
    0, 0,  0, 10, 20, 0
  ),
  nrow = 3,
  byrow = TRUE
)

cb_history <- crossbasis(
  X_history,
  lag = c(0, 5),
  argvar = list(fun = "lin"),
  arglag = list(fun = "ns", df = 3)
)

The outcome model must then match the study design; the cross-basis does not choose the correct likelihood for you.

12. Diagnostics and sensitivity analysis

Diagnose the complete regression, not just the surface

# Quasi-Poisson dispersion estimate
dispersion <- sum(
  residuals(fit_temp_nonlinear, type = "pearson")^2
) / df.residual(fit_temp_nonlinear)

dispersion

# Residual autocorrelation
acf(
  residuals(fit_temp_nonlinear, type = "pearson"),
  na.action = na.pass
)

# Rank and condition checks
X <- model.matrix(fit_temp_nonlinear)
c(columns = ncol(X), rank = qr(X)$rank)
kappa(crossprod(X))

Inspect residual time patterns, autocorrelation, leverage, overdispersion, boundary behavior, the distribution of observations across the exposure-lag grid, and whether important confounders have credible functional forms.

A disciplined sensitivity grid

Vary one design decision at a time and compare target summaries, not only surface appearance.

specifications <- expand.grid(
  max_lag = c(21, 30, 40),
  exposure_df = c(4, 5, 6),
  lag_df = c(4, 5),
  KEEP.OUT.ATTRS = FALSE
)

# For each row:
# 1. rebuild crossbasis();
# 2. refit the same confounder model;
# 3. predict at identical exposure values and reference;
# 4. compare selected cumulative RRs, uncertainty, and residual checks.

Quasi-Poisson models do not provide an ordinary maximum-likelihood AIC. Do not use AIC() mechanically as the sole model-selection rule. Scientific plausibility, pre-specification, effective complexity, uncertainty, and diagnostic stability all matter.

13. Advanced option — penalized DLNMs

Penalized models start with richer marginal bases and estimate smoothness using penalties. This can reduce the need to hand-select every degree of freedom, although the lag range, upper basis dimensions, confounders, and penalty structure still require judgment.

The external method is explicit and works with the familiar cross-basis:

cb_temp_penalized <- crossbasis(
  chicagoNMMAPS$temp,
  lag = 30,
  argvar = list(fun = "ps", df = 8),
  arglag = list(fun = "ps", df = 8)
)

penalty_temp <- cbPen(cb_temp_penalized)

fit_temp_penalized <- mgcv::gam(
  death ~ cb_temp_penalized + s(time, k = 100) + dow,
  family = quasipoisson(),
  data = chicagoNMMAPS,
  paraPen = list(cb_temp_penalized = penalty_temp),
  method = "REML"
)

pred_temp_penalized <- crosspred(
  cb_temp_penalized,
  fit_temp_penalized,
  at = seq(-20, 33, by = 1),
  cen = 25
)

dlnm also provides an internal mgcv smooth constructor used as s(X, L, bs = "cb"). It requires explicit matrices of exposure histories X and corresponding lags L; it is not a drop-in replacement that accepts the original vector. Consult the penalized vignette before using that route.

14. Migrating the 2011 paper code

The paper remains conceptually current, but its package calls predate the modern list-based API.

2011 style Current style
maxlag = 30 lag = 30
vartype = "bs", vardf = 6 argvar = list(fun = "bs", df = 6)
lagtype = "ns", lagdf = 5 arglag = list(fun = "ns", df = 5)
vartype = "hthr", varknots = 40.3 argvar = list(fun = "thr", thr = 40.3)
lagtype = "strata", lagknots = c(2, 6) arglag = list(fun = "strata", breaks = c(2, 6))
cenvalue = 25 inside crossbasis() cen = 25 in crosspred() or crossreduce()

An old call such as this should be read, not copied literally:

# Historical syntax from the paper — do not run with dlnm 2.4.10
# basis.temp <- crossbasis(
#   temp, vartype = "bs", vardf = 6,
#   cenvalue = 25, lagdf = 5, maxlag = 30
# )

Its current equivalent is:

basis_temp <- crossbasis(
  temp,
  lag = 30,
  argvar = list(fun = "bs", degree = 3, df = 6),
  arglag = list(fun = "ns", df = 5)
)

pred_temp <- crosspred(basis_temp, fitted_model, cen = 25)

Since dlnm 2.2.0, centering belongs at the prediction/reduction stage. Keeping it there makes clear that the reference value defines a contrast and does not alter model fitting.

15. Interpretation checklist and common mistakes

Before reporting a DLNM result, answer each question explicitly:

  1. What population, time unit, outcome family, and link were used?
  2. Is the exposure series complete, ordered, and equally spaced?
  3. Why is the maximum lag scientifically adequate?
  4. What functions, df, knots, and intercept rules define both basis dimensions?
  5. What exposure value is the reference, and is it supported by the data?
  6. Is the reported result lag-specific, incremental cumulative, or overall cumulative?
  7. Which temporal and time-varying confounders were adjusted, and how?
  8. How many rows were lost because of missing exposure histories?
  9. Are estimates at exposure extremes supported by enough observations?
  10. Are the principal conclusions stable under prespecified alternatives?

Common mistakes

  • Deleting dates before building the basis: corrupts lag spacing.
  • Putting an intercept in argvar: creates non-identifiability.
  • Using cen in crossbasis(): relies on obsolete behavior.
  • Calling crosspred() with a reconstructed basis: coefficient names or attributes may not match the fit.
  • Overfitting both dimensions: creates a large, unstable tensor product.
  • Treating the prettiest surface as the conclusion: 3-D perspective can hide uncertainty and sparse support.
  • Reading association as causation: DLNM controls functional form, not study-design bias.
  • Ignoring harvesting or displacement: short positive and later negative associations may offset in the cumulative estimate.
  • Comparing curves with different references: relative risks are not directly comparable until centering is aligned.

16. A compact reusable analysis skeleton

library(dlnm)
library(splines)

# 1. Audit time and missingness
stopifnot(!is.unsorted(dat$date))
stopifnot(all(diff(dat$date) == 1))
colSums(is.na(dat[c("outcome", "exposure", "date")]))

# 2. Define the basis once
cb_exposure <- crossbasis(
  dat$exposure,
  lag = 30,
  argvar = list(fun = "ns", df = 5),
  arglag = list(fun = "ns", knots = logknots(30, 3))
)
summary(cb_exposure)

# 3. Fit a prespecified outcome model
fit <- glm(
  outcome ~ cb_exposure + ns(time, df = 7 * years) + day_of_week,
  family = quasipoisson(),
  data = dat
)

# 4. Predict explicit contrasts
pred <- crosspred(
  cb_exposure,
  fit,
  at = prediction_grid,
  cen = reference_value,
  cumul = TRUE
)

# 5. Report complementary views
plot(pred, "contour")
plot(pred, "overall")
plot(pred, "slices", var = selected_exposure, ci = "lines")

# 6. Save compact estimates and provenance
overall <- crossreduce(cb_exposure, fit, type = "overall", cen = reference_value)
sessionInfo()

Treat lag, argvar, arglag, the confounder formula, prediction grid, reference, and target contrasts as analysis inputs worthy of version control—not as incidental plotting options.
