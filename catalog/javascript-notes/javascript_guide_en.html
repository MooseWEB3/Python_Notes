A Practical Guide to JavaScript

Understand how JavaScript runs, learn the language, DOM, events, async programming, and modules, then build a working todo application.

Beginner friendlyRunnable examplesInteractive exercisesBrowser + Node.js

This tutorial is a set of personal learning and practice notes.

Learning outcome: By the end of this guide, you will be able to read everyday JavaScript, add behavior to a web page, call web APIs, manage asynchronous work, and organize a small front-end project.

1. What is JavaScript?

JavaScript (JS) is a dynamic, prototype-based, multi-paradigm programming language. It began as a way to make web pages interactive. Today it also runs on servers, desktop and mobile apps, automation scripts, and embedded devices.

In the browser

Change page content, respond to clicks, validate forms, request server data, and create animation.

On the server

Use Node.js to build APIs, command-line tools, real-time services, and build scripts.

Across an ecosystem

npm offers a huge package registry. React, Vue, Svelte, and many other tools build on JavaScript.

The three core browser technologies divide responsibility like this:

Technology Responsibility Analogy
HTML Content and structure The frame of a house
CSS Presentation and layout Decoration and appearance
JavaScript Behavior and data Wiring and controls

JavaScript and Java are separate languages. Their similar names are historical; their type systems, runtimes, and common uses are different.

1.1 How JavaScript runs

Browsers contain a JavaScript engine: Chrome and Edge use V8, while Firefox uses SpiderMonkey. The engine parses and executes your code. A typical page works as follows:

  1. The browser parses HTML and creates the DOM (Document Object Model).
  2. It loads and executes JavaScript when it encounters a <script>.
  3. JavaScript reads or changes the DOM and registers event listeners.
  4. When a user clicks, a network response arrives, or a timer finishes, the event loop schedules the relevant callback.

A .js file is plain text and does not need a manual compilation step to run in a browser. Modern engines still compile and optimize code internally while the program runs.

2. Set up and run your first program

You need a modern browser and a text editor. Chrome, Edge, and Firefox all have capable developer tools. VS Code, RStudio, or any plain-text editor can create the files.

2.1 The browser console: the fastest experiment

Open a page, press F12 or Ctrl + Shift + I (macOS: Cmd + Option + I), choose Console, and enter:

console.log("Hello, JavaScript!");
2 + 3;

The console is excellent for testing expressions, inspecting values, and debugging. Keep production code in source files.

2.2 Include JavaScript in HTML

Create these two files:

<!-- index.html -->
<!doctype html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My JavaScript page</title>
  <script src="app.js" defer></script>
</head>
<body>
  <h1 id="title">Welcome</h1>
  <button id="hello-button">Click me</button>
</body>
</html>
// app.js
const title = document.querySelector("#title");
const button = document.querySelector("#hello-button");

button.addEventListener("click", () => {
  title.textContent = "JavaScript is running!";
});

The defer attribute waits until HTML parsing has finished, runs before DOMContentLoaded, and preserves the order of multiple deferred scripts. It is a good default for ordinary page scripts.

An inline <script> is useful for a tiny demo, but separate .js files are easier to reuse, cache, test, and maintain.

2.3 Run JavaScript with Node.js

After installing Node.js, run:

node --version
node app.js

Node.js does not provide the browser’s document or window. Instead, it exposes server-side capabilities such as files, networking, processes, and streams. Browser and Node programs share the core language but use different host APIs.

Suggested workflow: use the console for language experiments, .html + .js files and developer tools for pages, and Node.js for server or automation scripts.

3. Variables, values, and operators

3.1 const, let, and var

const siteName = "Learn JavaScript"; // cannot be reassigned
let score = 0;                       // may be reassigned
score = score + 10;

// Common in older code, but usually avoided in new code
var legacyValue = true;

Use const by default and let only when a binding must be reassigned. Avoid var in new code because it is function-scoped and has confusing hoisting behavior.

const prevents reassignment of the binding; it does not freeze an object’s contents:

const user = { name: "Kim" };
user.name = "Jo";        // valid: changes a property
// user = { name: "Sam" }; // error: reassigns a const

Type Example Meaning

3.3 Operators and strict equality

const total = 8 + 2;      // 10
const remainder = 10 % 3; // 1
const power = 2 ** 3;     // 8

5 === 5;    // true: same value and type
5 === "5";  // false
5 == "5";   // true: implicit conversion, best avoided

true && false;  // false
true || false;  // true
!true;          // false

Prefer === and !==. The coercion rules behind == and != are hard to scan and can hide bugs.

Nullish coalescing ?? uses a fallback only when the left side is null or undefined. Optional chaining ?. returns undefined if a path is missing:

const settings = { profile: { nickname: "Mia" }, volume: 0 };
const nickname = settings.profile?.nickname ?? "Anonymous";
const volume = settings.volume ?? 50; // remains 0

3.4 Strings and template literals

const name = "Alex";
const lessons = 6;
const message = `${name} completed ${lessons} lessons.`;

message.length;
message.toUpperCase();
message.includes("completed");
message.replace("6", "7");

Template literals use backticks, can include ${expressions}, and may span multiple lines.

4. Control flow

4.1 Conditions

const age = 20;

if (age >= 18) {
  console.log("Adult");
} else if (age >= 13) {
  console.log("Teenager");
} else {
  console.log("Child");
}

const ticket = age >= 18 ? "adult" : "student";

The following values are falsy: false, 0, -0, 0n, "", null, undefined, and NaN. Empty arrays [] and empty objects {} are truthy.

Use switch when one expression must be compared with several fixed values:

switch (new Date().getDay()) {
  case 0:
  case 6:
    console.log("Weekend");
    break;
  default:
    console.log("Weekday");
}

4.2 Loops

for (let i = 0; i < 3; i += 1) {
  console.log(i);
}

const colors = ["red", "green", "blue"];
for (const color of colors) {
  console.log(color); // iterates values
}

const person = { name: "Ana", role: "developer" };
for (const key in person) {
  console.log(key, person[key]); // iterates enumerable keys
}

Prefer for...of or array methods such as map, filter, and reduce for arrays. for...in is mainly for object keys and is a poor default for arrays.

5. Functions, scope, and closures

Functions package reusable behavior. A clear function usually does one job, takes input through parameters, and produces output with return.

function calculateTax(price, rate = 0.05) {
  return price * rate;
}

const double = function (value) {
  return value * 2;
};

const square = value => value ** 2;

console.log(calculateTax(100)); // 5
console.log(square(4));         // 16

Arrow functions are concise, but they do not have their own this, arguments, or prototype. A normal function is usually a better choice for methods or constructors that need dynamic this.

5.1 Scope

const appName = "Notes"; // global scope

function greet() {
  const message = "Hello"; // function scope

  if (true) {
    let punctuation = "!"; // block scope
    console.log(message + punctuation);
  }
}

Inner scopes can read variables from outer scopes; outer scopes cannot read variables declared inside. Keep scopes small to reduce accidental changes.

5.2 Closures

A function remembers the scope in which it was created. This behavior is called a closure:

function createCounter() {
  let count = 0;

  return function () {
    count += 1;
    return count;
  };
}

const nextCount = createCounter();
nextCount(); // 1
nextCount(); // 2

Closures are useful for private state, event handlers, and function factories. A long-lived closure that references a large object will also keep that object from being garbage-collected.

6. Arrays and objects: organizing data

6.1 Essential array methods

const products = [
  { name: "Keyboard", price: 80, inStock: true },
  { name: "Mouse", price: 35, inStock: false },
  { name: "Monitor", price: 420, inStock: true }
];

const names = products.map(product => product.name);
const available = products.filter(product => product.inStock);
const expensive = products.find(product => product.price > 400);
const total = products.reduce((sum, product) => sum + product.price, 0);
const allHaveNames = products.every(product => product.name.length > 0);
Method Returns Mutates input? Typical use
map New array of equal length No Transform each item
filter Filtered new array No Keep matching items
find First item or undefined No Find one item
some / every Boolean No Test conditions
reduce Any accumulated result No Sum, group, build objects
push / pop Length / removed item Yes Add/remove at the end
sort The original array Yes Sort; copy first when needed 
const sorted = [...products].sort((a, b) => a.price - b.price);

6.2 Objects, destructuring, and spread

const user = {
  id: 7,
  name: "Lina",
  address: { city: "Calgary" },
  greet() {
    return `Hello, I am ${this.name}`;
  }
};

const { name, address: { city } } = user;
const updatedUser = { ...user, name: "Nora" };

Object.keys(user);    // array of keys
Object.values(user);  // array of values
Object.entries(user); // array of [key, value]

Spread creates a shallow copy. updatedUser.address and user.address still refer to the same nested object. Use structuredClone(user) when you need a deep copy of supported data.

7. The DOM: controlling a web page

The DOM represents HTML as a tree of nodes. JavaScript can find nodes, change content and classes, and create new elements.

7.1 Find and update elements

const heading = document.querySelector("h1");
const firstCard = document.querySelector(".card");
const allButtons = document.querySelectorAll("button");

heading.textContent = "New safe text";
firstCard.classList.add("active");
firstCard.setAttribute("data-state", "ready");
allButtons.forEach(button => {
  button.disabled = false;
});

Selectors use CSS syntax: #id, .class, tag, and [attribute]. querySelector returns the first match or null; querySelectorAll returns a static NodeList.

7.2 Create elements safely

function addMessage(text) {
  const item = document.createElement("li");
  item.textContent = text;
  item.classList.add("message");
  document.querySelector("#messages").append(item);
}

Use textContent for untrusted text from users or servers. Assigning untrusted strings to innerHTML can create a cross-site scripting (XSS) vulnerability.

7.3 Classes and styles

const panel = document.querySelector(".panel");
panel.classList.toggle("is-open");
panel.style.setProperty("--panel-width", "320px");

Prefer defining visual states as CSS classes and switching those classes with classList. This keeps structure, presentation, and behavior separate.

8. Events: responding to users

<button id="save-button">Save</button>
const saveButton = document.querySelector("#save-button");

saveButton.addEventListener("click", event => {
  event.currentTarget.textContent = "Saved";
  console.log("Click position:", event.clientX, event.clientY);
});

Common events include click, input, change, submit, keydown, focus, and blur. event.target is where the event began; event.currentTarget is the element whose listener is currently running.

8.1 Form submission

<form id="signup-form">
  <label>Email <input name="email" type="email" required></label>
  <button>Sign up</button>
</form>
const form = document.querySelector("#signup-form");

form.addEventListener("submit", event => {
  event.preventDefault();
  const data = new FormData(form);
  const email = data.get("email").trim();

  if (!email.includes("@")) {
    console.error("Enter a valid email address");
    return;
  }

  console.log({ email });
});

Browser validation improves usability, but the server must validate every input again.

8.2 Event delegation

When a list is large or changes dynamically, put one listener on a common parent:

document.querySelector("#task-list").addEventListener("click", event => {
  const deleteButton = event.target.closest("[data-delete-id]");
  if (!deleteButton) return;

  deleteTask(deleteButton.dataset.deleteId);
});

Events bubble from children toward ancestors, so one parent listener can handle both current and future list items.

9. Asynchronous JavaScript, Promises, and requests

The JavaScript main thread runs one piece of synchronous code at a time. The environment handles timers and network operations. When those operations finish, the event loop schedules their callbacks. Asynchronous code lets the page remain responsive while it waits.

9.1 Promises

A Promise represents a result that may succeed or fail in the future. Its state is pending, fulfilled, or rejected.

function wait(milliseconds) {
  return new Promise(resolve => {
    setTimeout(resolve, milliseconds);
  });
}

wait(1000)
  .then(() => console.log("Runs after one second"))
  .catch(error => console.error(error))
  .finally(() => console.log("Finished"));

9.2 async / await

async function loadUser(userId) {
  try {
    const response = await fetch(`https://jsonplaceholder.typicode.com/users/${userId}`);

    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }

    const user = await response.json();
    return user;
  } catch (error) {
    console.error("Could not load user:", error);
    throw error;
  }
}

fetch rejects automatically only when the network operation itself fails. A 404 or 500 still produces a Response, so check response.ok.

Run independent requests in parallel:

const [user, posts] = await Promise.all([
  fetch("/api/user").then(response => response.json()),
  fetch("/api/posts").then(response => response.json())
]);

9.3 Cancel a request

const controller = new AbortController();

fetch("/api/search?q=javascript", { signal: controller.signal })
  .catch(error => {
    if (error.name !== "AbortError") throw error;
  });

controller.abort();

Canceling obsolete work is especially useful for live search and page transitions. It prevents an older response from replacing newer data.

10. Error handling and debugging

function parseSettings(jsonText) {
  try {
    const value = JSON.parse(jsonText);
    if (typeof value !== "object" || value === null) {
      throw new TypeError("Settings must be an object");
    }
    return value;
  } catch (error) {
    console.error(error.name, error.message);
    return {};
  }
}

A productive debugging sequence is:

  1. Read the first console error and its stack trace, not only the final line.
  2. Log names and values together with console.log({ variableA, variableB }).
  3. Set a breakpoint in the Sources panel, step through, and inspect Scope.
  4. Inspect URL, status, response, and timing in the Network panel.
  5. reduce the problem to the smallest reproducible code and test each assumption.
console.table(products);
console.time("calculation");
// code to measure
console.timeEnd("calculation");

debugger; // pauses here when developer tools are open

Do not hide failures in an empty catch {}. Record useful context or rethrow the error to code that can handle it.

11. Modules, classes, and organization

11.1 ES modules

// math.js
export const PI = 3.14159;
export function add(a, b) {
  return a + b;
}
// app.js
import { PI, add } from "./math.js";
console.log(add(PI, 2));
<script type="module" src="app.js"></script>

Modules use strict mode, have their own scope, and are deferred automatically. During local development, serve module-based projects through a development server instead of opening file:// directly, which can trigger browser origin restrictions.

11.2 Classes

JavaScript classes are a clearer syntax over prototype-based inheritance:

class BankAccount {
  #balance = 0;

  constructor(owner) {
    this.owner = owner;
  }

  deposit(amount) {
    if (amount <= 0) throw new RangeError("Amount must be positive");
    this.#balance += amount;
  }

  get balance() {
    return this.#balance;
  }
}

const account = new BankAccount("Mina");
account.deposit(100);
console.log(account.balance); // 100

Plain functions and objects are often enough for small data transformations. Classes become useful when many instances share behavior and need encapsulated state.

11.3 A simple project structure

my-app/
├── index.html
├── css/
│   └── styles.css
├── js/
│   ├── app.js          # startup and coordination
│   ├── api.js          # network requests
│   ├── storage.js      # local persistence
│   └── ui.js           # DOM updates
└── assets/

Split files by responsibility instead of growing one enormous app.js. Module names should describe an area of responsibility. Function names should use verbs such as loadTasks, renderList, and validateEmail.

12. Browser storage and JSON

localStorage persists strings for one website:

const preferences = { theme: "dark", fontSize: 18 };

localStorage.setItem("preferences", JSON.stringify(preferences));

const savedText = localStorage.getItem("preferences");
const savedPreferences = savedText ? JSON.parse(savedText) : {};

localStorage.removeItem("preferences");

localStorage is synchronous, limited in size, and editable by the user. Never store passwords, access tokens, or sensitive personal data in it, and do not treat it as a trusted database.

Option Lifetime Good for
localStorage Until explicitly removed Small preferences and drafts
sessionStorage Current tab session Temporary flow state
Cookie Configurable; sent with requests Server sessions with secure attributes
IndexedDB Persistent, larger capacity Offline and structured records

13. Complete example: todo list

This example combines state, rendering, event delegation, and local storage. The demo on this page is fully interactive.

0 tasks

The core implementation can look like this:

const STORAGE_KEY = "javascript-guide-tasks";
let tasks = JSON.parse(localStorage.getItem(STORAGE_KEY) ?? "[]");

function saveTasks() {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(tasks));
}

function addTask(text) {
  const cleanText = text.trim();
  if (!cleanText) return;

  tasks.push({
    id: crypto.randomUUID(),
    text: cleanText,
    done: false
  });
  saveTasks();
  renderTasks();
}

function toggleTask(id) {
  tasks = tasks.map(task =>
    task.id === id ? { ...task, done: !task.done } : task
  );
  saveTasks();
  renderTasks();
}

function deleteTask(id) {
  tasks = tasks.filter(task => task.id !== id);
  saveTasks();
  renderTasks();
}

function renderTasks() {
  const list = document.querySelector("#todo-list");
  list.replaceChildren();

  for (const task of tasks) {
    const item = document.createElement("li");
    item.classList.toggle("done", task.done);

    const checkbox = document.createElement("input");
    checkbox.type = "checkbox";
    checkbox.checked = task.done;
    checkbox.dataset.toggleId = task.id;

    const label = document.createElement("span");
    label.textContent = task.text;

    const deleteButton = document.createElement("button");
    deleteButton.textContent = "Delete";
    deleteButton.dataset.deleteId = task.id;

    item.append(checkbox, label, deleteButton);
    list.append(item);
  }
}

This version deliberately separates “change state” from “render the interface.” As an application grows, that one-way flow is easier to reason about than unrelated DOM mutations scattered throughout the code.

14. Code quality, performance, and security

14.1 Reliability checklist

  • Use meaningful names instead of x1 and data2.
  • Default to const; use let for real reassignment.
  • Validate external inputs and fail early at boundaries.
  • Keep functions focused on one clear responsibility.
  • Use ESLint to find likely errors and Prettier for consistent formatting.
  • Automate tests for important behavior instead of relying only on manual clicks.
  • Write comments that explain why, not a line-by-line translation of what.

14.2 Performance principles

  • Measure before optimizing; use the Performance panel to locate bottlenecks.
  • Avoid repeatedly forcing layout inside loops; batch DOM updates.
  • Debounce or throttle scroll, resize, and live-search handlers.
  • Load images and non-critical modules only when needed.
  • Use pagination, virtualization, or a DocumentFragment for very large lists.
function debounce(fn, delay = 250) {
  let timerId;
  return (...args) => {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), delay);
  };
}

const search = debounce(query => {
  console.log("Search:", query);
});

14.3 Security baseline

  • Never put private API keys or database passwords in front-end JavaScript. Everyone can download browser code.
  • Never concatenate user input into innerHTML, eval, or new Function.
  • Keep dependencies updated and review security advisories.
  • Enforce authorization and validation on the server. Client checks are a usability feature, not a security boundary.
  • Use HTTPS, a Content Security Policy (CSP), and secure cookie attributes.
