1. What this guide is for

This guide is a complete, standalone workflow for high-dimensional modeling: determine whether the problem is multiple testing, prediction, variable selection, or inference; choose a penalty, validation design, and metric; then report stability and uncertainty. Every concept, warning, and code example needed by the tutorial is included on the page, with no dependency on external lecture notes, course scripts, or a textbook file.

Examples are not executed automatically so the page does not install optional packages or start long simulations. Copy one section at a time into a clean R session and adapt parameters to the structure of your data.

After working through the guide, you should be able to:

  • explain why ordinary least squares becomes unstable when p approaches or exceeds n;
  • compare Ridge, Lasso, Elastic Net, MCP, and SCAD under the same data split;
  • distinguish training error, cross-validation error, independent test error, and post-selection inference;
  • choose suitable penalties for binary, survival, grouped, interaction, and ordered data;
  • organize data auditing, tuning, independent assessment, stability analysis, and reporting into a reproducible workflow.

The most important habit is to separate model selection from model assessment. Selecting variables on all observations and then reporting ordinary lm() p-values on those same observations is not valid post-selection inference.

3. Start with a controlled high-dimensional simulation

Real data do not reveal which variables are true signals. Validate the workflow on a simulation before applying it to course data. The function below creates an AR(1)-correlated design with only the first s coefficients active.

R
simulate_hd <- function(n = 160, p = 500, s = 12,
                        rho = 0.45, sigma = 1) {
  stopifnot(n > 10, p >= s, s >= 1, abs(rho) < 1)
  X <- matrix(0, nrow = n, ncol = p)
  X[, 1] <- rnorm(n)
  for (j in 2:p) {
    X[, j] <- rho * X[, j - 1] + sqrt(1 - rho^2) * rnorm(n)
  }
  X <- scale(X)
  beta <- numeric(p)
  beta[seq_len(s)] <- rep(c(1.5, -1.25, 0.9), length.out = s)
  y <- drop(X %*% beta + rnorm(n, sd = sigma))
  colnames(X) <- sprintf("X%03d", seq_len(p))
  list(X = X, y = y, beta = beta, active = seq_len(s))
}

dat <- simulate_hd()
c(n = nrow(dat$X), p = ncol(dat$X), signals = length(dat$active))

4. Large-scale univariate testing: FWER, FDR, and local FDR

Large-scale testing begins by deciding whether to control the probability of any false positive or the false proportion among discoveries. Holm, Bonferroni, and Westfall-Young primarily control FWER; Benjamini-Hochberg controls FDR; local FDR gives an item-level posterior null probability. Empirical-Bayes methods can also stabilize variance estimates by sharing information across features.

4.1 Choose the error target first

score_discoveries <- function(selected, truth) {
  selected <- as.logical(selected)
  truth <- as.logical(truth)
  c(
    selected = sum(selected),
    false_discoveries = sum(selected & !truth),
    fdp = sum(selected & !truth) / max(sum(selected), 1),
    power = sum(selected & truth) / max(sum(truth), 1)
  )
}

rbind(
  Holm = score_discoveries(discoveries$holm, is_signal),
  BH_10 = score_discoveries(discoveries$bh_10, is_signal)
)

4.2 A simplified local-FDR estimate

The central local-FDR idea is to estimate the marginal density f(z) and evaluate \pi_0 f_0(z)/f(z). The next block is a simplified teaching implementation; for formal work, prefer a validated empirical-Bayes implementation such as fdrtool.

R
local_null_probability <- function(statistic, pi0 = 0.95,
                                   null_mean = 0, null_sd = 1) {
  marginal <- density(statistic, bw = "SJ", n = 4096)
  marginal_at_z <- approxfun(
    marginal$x, marginal$y,
    yleft = marginal$y[1], yright = tail(marginal$y, 1)
  )
  null_component <- pi0 * dnorm(statistic, null_mean, null_sd)
  estimate <- null_component /
    pmax(marginal_at_z(statistic), sqrt(.Machine$double.eps))
  pmin(1, pmax(0, estimate))
}

lfdr <- local_null_probability(z, pi0 = 0.95)
head(data.frame(z = z, p = p_value, lfdr = lfdr)[order(lfdr), ], 10)

5. Ridge: a stable baseline for correlated predictors and prediction

When two or more predictors are nearly collinear, OLS coefficients can become unstable. Ridge adds an L_2 penalty and usually does not produce exact zero coefficients, making it a strong baseline when many predictors may have small effects or prediction is the primary goal.

\hat\beta^{ridge}(\lambda)=\arg\min_\beta\left\{\frac{1}{2n}\lVert y-X\beta\rVert_2^2+\lambda\lVert\beta\rVert_2^2\right\}

6. Lasso: sparse selection, soft thresholding, and coordinate descent

Lasso adds an L_1 penalty, allowing coefficients to become exactly zero. KKT conditions characterize the optimum, soft thresholding explains coefficient updates under an orthogonal design, and coordinate descent efficiently calculates the full regularization path.

R
soft_threshold <- function(z, lambda) {
  sign(z) * pmax(abs(z) - lambda, 0)
}

z_grid <- seq(-3, 3, length.out = 13)
data.frame(
  z = z_grid,
  soft_0_5 = soft_threshold(z_grid, 0.5),
  soft_1_0 = soft_threshold(z_grid, 1.0)
)

Save the complete fitted path rather than only the final coefficient vector.

R
lasso_cv <- glmnet::cv.glmnet(
  x_train, y_train,
  alpha = 1,
  foldid = foldid,
  standardize = TRUE,
  type.measure = "mse",
  keep = TRUE
)

lasso_beta_min <- drop(coef(lasso_cv, s = "lambda.min"))
lasso_beta_1se <- drop(coef(lasso_cv, s = "lambda.1se"))
c(
  selected_min = sum(lasso_beta_min[-1] != 0),
  selected_1se = sum(lasso_beta_1se[-1] != 0)
)

lambda.min minimizes estimated CV error. lambda.1se uses more shrinkage while remaining within one standard error of the minimum, usually producing a smaller and more stable model.

7. Cross-validation: tune lambda and assess honestly

Effective degrees of freedom, information criteria, and cross-validation answer different questions. Tuning by CV does not by itself provide an independent generalization estimate. If the same CV result chooses the model and supports the performance claim, optimism can remain.

7.1 Use one metric function

R
regression_metrics <- function(observed, predicted) {
  residual <- observed - predicted
  c(
    RMSE = sqrt(mean(residual^2)),
    MAE = mean(abs(residual)),
    R2 = 1 - sum(residual^2) / sum((observed - mean(observed))^2)
  )
}

lasso_pred_min <- drop(predict(lasso_cv, x_test, s = "lambda.min"))
lasso_pred_1se <- drop(predict(lasso_cv, x_test, s = "lambda.1se"))

rbind(
  Ridge = regression_metrics(y_test, ridge_pred),
  Lasso_min = regression_metrics(y_test, lasso_pred_min),
  Lasso_1se = regression_metrics(y_test, lasso_pred_1se)
)

7.2 Nested cross-validation skeleton

When the sample is too small for a fixed test set, use outer CV for performance and inner CV for lambda selection.

R
nested_cv_glmnet <- function(X, y, outer_k = 5, inner_k = 5, alpha = 1,
                             seed = 7240) {
  set.seed(seed)
  outer_fold <- sample(rep(seq_len(outer_k), length.out = length(y)))
  prediction <- rep(NA_real_, length(y))
  chosen_lambda <- numeric(outer_k)

  for (k in seq_len(outer_k)) {
    assessment <- outer_fold == k
    analysis <- !assessment
    set.seed(seed + k)
    inner_fold <- sample(rep(seq_len(inner_k), length.out = sum(analysis)))
    fit <- glmnet::cv.glmnet(
      X[analysis, , drop = FALSE], y[analysis],
      alpha = alpha, foldid = inner_fold, standardize = TRUE
    )
    chosen_lambda[k] <- fit$lambda.min
    prediction[assessment] <- drop(predict(
      fit, X[assessment, , drop = FALSE], s = "lambda.min"
    ))
  }

  list(
    prediction = prediction,
    lambda = chosen_lambda,
    metrics = regression_metrics(y, prediction)
  )
}

8. Adaptive Lasso, MCP, and SCAD: reducing large-signal bias

Lasso, Adaptive Lasso, MCP, and SCAD have different thresholding rules and solution paths. A frequently missed point is that Adaptive Lasso weights are estimated from data, so the entire two-stage procedure belongs inside cross-validation.

8.1 Adaptive Lasso

R
initial <- glmnet::cv.glmnet(
  x_train, y_train, alpha = 0,
  foldid = foldid, standardize = TRUE
)
initial_beta <- abs(drop(coef(initial, s = "lambda.min"))[-1])
penalty_weight <- 1 / pmax(initial_beta, 1e-4)

adaptive_cv <- glmnet::cv.glmnet(
  x_train, y_train,
  alpha = 1,
  penalty.factor = penalty_weight,
  foldid = foldid,
  standardize = TRUE
)

This code is useful for demonstration. In formal assessment, re-estimate initial_beta inside each training fold; otherwise validation information leaks into the weights.

9. Elastic Net: stabilize correlated predictors

Elastic Net adds an L_2 component to Lasso and often retains correlated groups more stably. Average absolute correlation, cumulative PCA variance, and effective rank help identify strong dependence or low-rank structure in the design matrix.

R
alpha_grid <- c(0, 0.25, 0.5, 0.75, 1)
enet_fits <- lapply(alpha_grid, function(a) {
  glmnet::cv.glmnet(
    x_train, y_train,
    alpha = a,
    foldid = foldid,
    standardize = TRUE,
    type.measure = "mse"
  )
})

enet_table <- do.call(rbind, lapply(seq_along(enet_fits), function(i) {
  fit <- enet_fits[[i]]
  pred <- drop(predict(fit, x_test, s = "lambda.min"))
  beta <- drop(coef(fit, s = "lambda.min"))[-1]
  data.frame(
    alpha = alpha_grid[i],
    lambda = fit$lambda.min,
    selected = sum(beta != 0),
    RMSE = regression_metrics(y_test, pred)["RMSE"]
  )
}))
enet_table

If several alpha values have practically indistinguishable outer-CV or test performance, favor the simpler and more stable choice that matches the scientific structure instead of optimizing the third decimal place.

10. Compare sparsity and stability, not only prediction error

High-dimensional models can have similar RMSE but select very different variables. Repeated half-samples can estimate how often each variable is selected, which is more informative than one Lasso nonzero list.

R
stability_selection <- function(X, y, lambda, B = 100, fraction = 0.5,
                                seed = 7240) {
  set.seed(seed)
  p <- ncol(X)
  selected <- matrix(FALSE, nrow = B, ncol = p)
  for (b in seq_len(B)) {
    id <- sample(seq_len(nrow(X)), size = floor(fraction * nrow(X)))
    fit <- glmnet::glmnet(
      X[id, , drop = FALSE], y[id],
      alpha = 1, lambda = lambda, standardize = TRUE
    )
    selected[b, ] <- drop(coef(fit))[-1] != 0
  }
  probability <- colMeans(selected)
  names(probability) <- colnames(X)
  sort(probability, decreasing = TRUE)
}

selection_probability <- stability_selection(
  x_train, y_train, lambda = lasso_cv$lambda.1se, B = 50
)
head(selection_probability, 15)

Report at least:

  • outer-CV or independent-test prediction error;
  • final number of nonzero coefficients;
  • resampling selection probabilities;
  • Jaccard similarity of selected sets across folds or seeds;
  • improvement over a simple baseline such as the mean, clinical variables, or Ridge.

11. Inference after variable selection

Marginal FDR, semi-penalized tests, sample splitting, bootstrap, and selective inference answer different questions. Before choosing a method, state whether the target is prediction, discovery control, a pre-specified effect, or an interval conditional on the selection event.

11.1 Simple sample splitting

R
set.seed(900)
selection_id <- sample(seq_len(nrow(x_train)), floor(nrow(x_train) / 2))
inference_id <- setdiff(seq_len(nrow(x_train)), selection_id)

select_fit <- glmnet::cv.glmnet(
  x_train[selection_id, , drop = FALSE], y_train[selection_id],
  alpha = 1, standardize = TRUE

selected <- which(drop(coef(select_fit, s = "lambda.1se"))[-1] != 0)

  infer_data <- data.frame(
    y = y_train[inference_id],
    x_train[inference_id, selected, drop = FALSE]

  inference_fit <- lm(y ~ ., data = infer_data)

}

Splitting sacrifices efficiency but has a transparent logic. If splits are repeated and p-values aggregated, pre-specify the aggregation rule rather than reporting the most favorable split.

11.3 Knockoff filtering

The knockoff filter compares how early original and constructed knockoff variables enter a regularization path. Fixed-X knockoffs commonly need sufficient sample dimension; model-X or second-order constructions instead depend on estimating the distribution or covariance of X.

12. Binary outcomes and other likelihoods

A serious evaluation mistake in penalized logistic regression is drawing ROC or precision-recall curves from in-sample linear predictors and treating them as generalization estimates. Use out-of-fold predictions or a held-out test set.

12.1 Penalized logistic regression

R
set.seed(301)

Compute rank-based AUC without an extra dependency and report probability-sensitive metrics as well.

R
binary_metrics <- function(y, probability) {
  probability <- pmin(pmax(probability, 1e-8), 1 - 1e-8)
  n1 <- sum(y == 1)
  n0 <- sum(y == 0)
  auc <- (sum(rank(probability)[y == 1]) - n1 * (n1 + 1) / 2) / (n1 * n0)
  c(
    AUC = auc,
    LogLoss = -mean(y * log(probability) + (1 - y) * log(1 - probability)),
    Brier = mean((y - probability)^2)
  )
}
binary_metrics(y_binary[test_binary], probability)

13. Group Lasso and bi-level selection

When several columns jointly represent one scientific object, column-wise Lasso can produce incomplete and hard-to-interpret selections. Group Lasso selects or removes complete groups, while bi-level penalties go further when both group-level and within-group sparsity are desired.

R

Only some variables matter within an active groupGroup and within-group sparsitySparse Group Lasso / GEL

14. Interactions and hierarchy

Ordinary Lasso on the complete second-order design, glinternet, and sprintr can all screen interactions. With p main effects there are roughly p(p-1)/2 pairwise interactions, so memory use and overfitting grow quickly.

R
set.seed(2026)
n_int <- 144
p_int <- 18
X_int <- matrix(rnorm(n_int * p_int), n_int, p_int)
colnames(X_int) <- paste0("feature_", seq_len(p_int))
y_int <- 0.8 * X_int[, 2] - 0.6 * X_int[, 6] +
  1.3 * X_int[, 2] * X_int[, 5] + rnorm(n_int, sd = 0.9)

expanded <- model.matrix(~ (.)^2, data = as.data.frame(X_int))[, -1]
dim(expanded)

interaction_cv <- glmnet::cv.glmnet(expanded, y_int, alpha = 1)
interaction_beta <- drop(coef(interaction_cv, s = "lambda.1se"))[-1]
head(sort(abs(interaction_beta), decreasing = TRUE), 15)

Strong hierarchy requires both main effects whenever interaction X_jX_k is selected. Ordinary Lasso does not guarantee this. Use glinternet, hierNet, or another explicitly hierarchical method when scientific interpretation requires hierarchy.

15. Fusion, trend filtering, and ordered structure

Fusion methods put the belief that neighboring coefficients should be similar directly into the penalty. Fused Lasso applies an L_1 penalty to first differences and is useful for copy-number data, ordered time signals, images, and spatial sequences.

\frac{1}{2}\lVert y-\theta\rVert_2^2 + \lambda_1\sum_j|\theta_j| + \lambda_2\sum_{j=2}^p|\theta_j-\theta_{j-1}|
R
set.seed(991)
segment_level <- c(0, 1.2, -0.7, -0.7, 0.5)
segment_length <- c(24, 34, 18, 27, 31)
truth <- rep(segment_level, times = segment_length)
signal <- truth + rt(length(truth), df = 8) * 0.32

if (requireNamespace("genlasso", quietly = TRUE)) {
  trend_fit <- genlasso::trendfilter(signal, ord = 0)
  theta_small <- coef(trend_fit, lambda = 0.5)$beta
  theta_large <- coef(trend_fit, lambda = 2)$beta
}

Larger lambda gives fewer change points and smoother segments. Tune it with blocked or deployment-faithful validation; randomly shuffling ordered observations can create an unrealistically easy task.

16. Splines, sparse PCA, and graphical models

The same regularization ideas extend to nonlinear functions, dimension reduction, and precision matrices. These are not unrelated tricks: each controls high-dimensional freedom by imposing sparsity or structure.

16.1 Expand spline bases, then select groups

17. End-to-end project template

The following order works for most high-dimensional regression projects. Each step creates an auditable object instead of preserving only the final figure.

R
project_plan <- list(
  question = "Predict the outcome and identify stable candidate features",
  unit_of_analysis = "one independent subject per row",
  primary_metric = "outer-CV RMSE",
  secondary_metrics = c("MAE", "R2", "model size", "selection stability"),
  candidate_models = c("ridge", "lasso", "elastic net", "MCP"),
  inference_target = "exploratory variable discovery",
  fdr_target = 0.10
)
saveRDS(project_plan, "artifacts/analysis-plan.rds")

model_results

A final report should answer five questions:

  1. What are the sample, outcome, candidate predictors, and independent unit?
  2. Was every preprocessing step estimated only on training data or inside each fold?
  3. How were lambda, alpha, gamma, groups, and thresholds chosen?
  4. Does generalization error come from an independent test set or outer CV?
  5. Are nonzero variables predictive features, stable discoveries, or effects with valid uncertainty quantification?

18. Suggested learning path and completion checklist

For the fastest route to practical competence, work through:

  1. Use the Section 3 simulation to understand p>n, collinearity, and sparse truth;
  2. Compare Ridge, Lasso, nonconvex penalties, and Elastic Net in Sections 5-9;
  3. Use nested CV in Section 7 to build an honest performance estimate;
  4. Use Sections 10-11 to separate selection stability, discovery control, and valid inference;
  5. Choose among the classification, grouped, interaction, ordered, and nonlinear models in Sections 12-16 according to the data structure;
  6. Organize a complete analysis with the project template in Section 17.
Completion criterionMinimum requirement
Data auditMissingness, zero variance, duplicates, p/n, and group/time structure recorded
Leakage preventionPreprocessing, screening, and weight estimation occur inside training folds
Fair comparisonAll candidates share the same outer split and fold IDs
Performance reportAt least one independent or outer-CV metric with uncertainty
StabilityReport model size and resampling selection probabilities
Inference languageDistinguish predictors, discoveries, and inferential effects
ReproducibilitySave indices, folds, fits, metrics, and sessionInfo()

The key to high-dimensional modeling is not reproducing one figure. It is connecting the objective, penalty, validation design, and inferential claim into one leakage-resistant, interpretable, and reproducible workflow.
