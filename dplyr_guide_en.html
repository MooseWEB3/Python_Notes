What this guide teaches

dplyr is the core tidyverse package for data manipulation. A small, stable vocabulary of verbs covers selecting columns, filtering rows, creating variables, grouped summaries, and table joins. The closest Python tool is usually pandas, with NumPy supplying vectorized conditional operations.

This guide does more than translate function names. For every family of operations, it explains:

  • what the dplyr function accepts and returns;
  • how the operation composes in a pipeline;
  • the corresponding pandas or NumPy pattern;
  • where the two interfaces have different semantics;
  • common grouping, missing-value, index, and join mistakes.

Four core differences to understand first

  1. R positions start at 1; pandas .iloc positions start at 0.
  2. dplyr verbs normally return a new tibble without modifying the input. Most pandas methods also return a new object, but df["x"] = ... mutates df.
  3. group_by() attaches persistent grouping metadata. pandas groupby() returns a GroupBy object that is normally consumed by aggregation or transformation.
  4. dplyr uses data masking, so a verb can refer to salary directly. pandas normally uses df["salary"], or column names inside a query() string.

Pipelines are also expressed differently:

R
employees |>
  filter(active) |>
  select(name, dept, salary)
Python
#| eval: false

(employees
 .loc[lambda d: d["active"], ["name", "dept", "salary"]])

R's |> sends the left side into a function. pandas generally uses method chaining, with lambda d: referring to the current object in a chain.

Filtering rows: filter()

Comparisons, logic, and membership

R
employees |> filter(active, salary >= 80000)
employees |> filter(dept %in% c("Data", "HR"))
employees |> filter(between(salary, 75000, 95000))
employees |> filter(name != "Ada" | city == "Calgary")
Python
#| eval: false

employees.loc[employees["active"] & employees["salary"].ge(80000)]
employees.loc[employees["dept"].isin(["Data", "HR"])]
employees.loc[employees["salary"].between(75000, 95000)]
employees.loc[employees["name"].ne("Ada") | employees["city"].eq("Calgary")]

Python uses &, |, and ~ for element-wise logic. Parenthesize each expression. Scalar operators and, or, and not cannot combine Series.

query() syntax

Python
#| eval: false

minimum = 80000
employees.query("active and salary >= @minimum")
employees.query("dept in ['Data', 'HR']")

query() is compact, but a string expression is more sensitive to unusual column names, IDE refactoring, and external-variable scope. Ordinary Boolean indexing is more explicit.

Missing-value filters

R

employees |> filter(!is.na(salary))
Python
#| eval: false

employees.loc[employees["salary"].isna()]
employees.loc[employees["salary"].notna()]

Do not compare with salary == NA or series == np.nan; missing values require dedicated predicates.

Temporary grouping with .by

Sorting: arrange() and desc()

R
employees |> arrange(dept, desc(salary), name)
employees |> arrange(is.na(salary), salary)
Python
#| eval: false

employees.sort_values(
    ["dept", "salary", "name"],
    ascending=[True, False, True],

arrange() places missing values last by default, even with desc(). pandas controls this with na_position. Order is critical before lags, cumulative calculations, and “first row per group” logic.

Creating and changing columns: mutate()

R
employees |>
  mutate(
    total_pay = salary + coalesce(bonus, 0),
    tenure_days = as.integer(Sys.Date() - joined),
    high_paid = salary >= 85000,

  )
Python
#| eval: false

result = employees.assign(
    total_pay=lambda d: d["salary"] + d["bonus"].fillna(0),

Later expressions in one dplyr mutate() can use columns just created. In pandas assign(), use lambda d: when a new expression depends on the current chained result.

Dropping columns and transmute()

R

Conditional transformations: if_else(), case_when(), case_match()

Two branches: if_else()

R
employees |>
  mutate(status = if_else(active, "Active", "Inactive", missing = "Unknown"))
Python
#| eval: false

employees.assign(status=np.where(employees["active"], "Active", "Inactive"))

if_else() enforces compatible output types and can explicitly handle a missing condition. NumPy where() may promote dtype.

Multiple conditions: case_when()

R
employees |>
  mutate(pay_band = case_when(
    is.na(salary) ~ "Unknown",
    salary >= 95000 ~ "A",
    salary >= 80000 ~ "B",
    TRUE ~ "C"
  ))
Python
#| eval: false

conditions = [
    employees["salary"].isna(),
    employees["salary"].ge(95000),
    employees["salary"].ge(80000),
]
employees.assign(pay_band=np.select(conditions, ["Unknown", "A", "B"], default="C"))

Conditions are matched in order, so write the most specific case or highest threshold first.

Exact mapping: case_match()

R
employees |>
  mutate(dept_code = case_match(
    dept,
    "Data" ~ "D",
    "Sales" ~ "S",
    "HR" ~ "H",
    .default = "Other"
  ))
Python
#| eval: false

mapping = {"Data": "D", "Sales": "S", "HR": "H"}
employees.assign(dept_code=employees["dept"].map(mapping).fillna("Other"))

case_match() is the clear modern choice for exact-value mappings. Older code often uses recode().

Missing-value helpers: coalesce() and na_if()

R
employees |>
  mutate(
    bonus_filled = coalesce(bonus, 0),
    salary_or_bonus = coalesce(salary, bonus),
    dept_clean = na_if(dept, "Unknown")
  )
Python
#| eval: false

employees.assign(
    bonus_filled=employees["bonus"].fillna(0),
    salary_or_bonus=employees["salary"].combine_first(employees["bonus"]),
    dept_clean=employees["dept"].replace("Unknown", pd.NA),
)

coalesce(x, y, z) selects the first non-missing value at each position. In pandas, chain combine_first() when more than two inputs are involved.

Grouping: group_by(), ungroup(), and .by

R
grouped <- employees |> group_by(dept)
group_vars(grouped)
group_keys(grouped)

grouped |>
  mutate(dept_mean = mean(salary, na.rm = TRUE)) |>
  ungroup()
Python
#| eval: false

grouped = employees.groupby("dept", dropna=False)
employees.assign(
    dept_mean=grouped["salary"].transform("mean")
)

transform() returns an object aligned to the original rows and is the closest pandas equivalent to grouped mutate(). agg() usually reduces rows and is closer to summarise().

When grouping is needed once, prefer .by:

R
employees |>
  mutate(dept_mean = mean(salary, na.rm = TRUE), .by = dept)

This avoids an accidental persistent group when ungroup() is forgotten.

Grouped summary

R
employees |>
  summarise(
    employees = n(),
    avg_salary = mean(salary, na.rm = TRUE),
    max_salary = max(salary, na.rm = TRUE),

#| eval: false

(employees.groupby("dept", as_index=False, dropna=False)

pandas named aggregation uses (input_column, aggregation) and maps cleanly to named dplyr summaries. size counts rows; count excludes missing values.

Controlling result grouping with .groups

R
employees |>
  group_by(city, dept) |>
  summarise(avg_salary = mean(salary, na.rm = TRUE), .groups = "drop")

Common values are "drop_last", "drop", "keep", and "rowwise". An explicit choice makes downstream behavior more predictable.

Arbitrary row counts: reframe()

summarise() requires one value per expression and group. reframe() allows each group to return any number of rows and always returns an ungrouped result.

R
employees |>
  reframe(
    quantile = c(0.25, 0.5, 0.75),
    salary = quantile(salary, c(0.25, 0.5, 0.75), na.rm = TRUE),
    .by = dept
  )
Python
#| eval: false

q = [0.25, 0.5, 0.75]
result = (employees.groupby("dept")["salary"]
          .quantile(q)
          .rename("salary")
          .rename_axis(index=["dept", "quantile"])
          .reset_index())

pandas has no single identically scoped method. Depending on the task, use quantile(), apply(), or an aggregation followed by index reshaping.

pick() and row reductions

pick() returns a data frame of selected columns inside a data-masking verb:

R
employees |>
  mutate(pay_total = rowSums(pick(salary, bonus), na.rm = TRUE))
Python
#| eval: false

employees.assign(pay_total=employees[["salary", "bonus"]].sum(axis=1, skipna=True))

For custom row-wise work:

R
employees |>
  rowwise() |>
  mutate(max_component = max(c_across(c(salary, bonus)), na.rm = TRUE)) |>

Python
#| eval: false

employees.assign(max_component=employees[["salary", "bonus"]].max(axis=1, skipna=True))

Prefer vectorized reductions such as rowSums(), pmax(), or pandas built-ins over R rowwise() and pandas apply(axis=1) when possible.

if_any() and if_all()

Build one row-level condition across several columns:

R
employees |> filter(if_any(c(salary, bonus), is.na))
employees |> filter(if_all(c(salary, bonus), ~ .x >= 70000))
Python
#| eval: false

pay = employees[["salary", "bonus"]]
employees.loc[pay.isna().any(axis=1)]
employees.loc[pay.ge(70000).all(axis=1)]

if_any() needs at least one selected column to pass; if_all() requires every selected column. Decide whether missing values should propagate, be treated as false, or be filled first.

Counting: count(), tally(), and add_count()

R
employees |> count(dept, sort = TRUE)
employees |> count(dept, wt = salary, name = "salary_total")

Python
#| eval: false

Window functions: lags, ranks, and cumulative operations

Previous and next values

R
reviews |>
  arrange(id, year) |>
  mutate(
    previous = lag(score),
    change = score - previous,
    next_score = lead(score),
    .by = id
  )
Python
#| eval: false

reviews_sorted = reviews.sort_values(["id", "year"])
reviews_sorted = reviews_sorted.assign(
    previous=lambda d: d.groupby("id")["score"].shift(1),
    change=lambda d: d["score"] - d["previous"],
    next_score=lambda d: d.groupby("id")["score"].shift(-1),
)

Window results depend on ordering. Unless you use order_by, sort before applying lag() or shift().

Ranking

R
employees |>
  mutate(
    row_rank = row_number(desc(salary)),
    min_rank = min_rank(desc(salary)),
    dense_rank = dense_rank(desc(salary)),
    quartile = ntile(salary, 4),
    .by = dept
  )
Python
#| eval: false

g = employees.groupby("dept")["salary"]
employees.assign(
    row_rank=g.rank(method="first", ascending=False),
    min_rank=g.rank(method="min", ascending=False),
    dense_rank=g.rank(method="dense", ascending=False),
    quartile=g.transform(lambda s: pd.qcut(s, 4, labels=False, duplicates="drop") + 1),
)

Tie handling must be deliberate. ntile() attempts to divide rows evenly and can split equal values; qcut() has its own boundary and duplicate-edge semantics.

Cumulative and rolling operations

R
reviews |>
  arrange(id, year) |>
  mutate(
    running_total = cumsum(score),
    running_mean = cummean(score),
    best_so_far = cummax(score),
    .by = id
  )
Python
#| eval: false

ordered = reviews.sort_values(["id", "year"])
g = ordered.groupby("id")["score"]
result = ordered.assign(
    running_total=g.cumsum(),
    running_mean=g.expanding().mean().reset_index(level=0, drop=True),

)

dplyr itself does not provide fixed-width rolling means. R users commonly use slider, zoo, or RcppRoll; pandas provides rolling().

    first_score="first",
    last_score="last",
    second_score=lambda s: s.iloc[1] if len(s) > 1 else np.nan,
).reset_index()

Always define order before taking first or last values.

Goal: keep active employees, replace missing bonuses with zero, compute total pay, summarize by department, and attach budget data.

  filter(active) |>
  mutate(total_pay = salary + coalesce(bonus, 0)) |>

    employees = n(),
    payroll = sum(total_pay, na.rm = TRUE),
    avg_pay = mean(total_pay, na.rm = TRUE),
    .by = dept
  ) |>

Python

Important semantic traps

Missing values

  • dplyr aggregations often need na.rm = TRUE; many pandas aggregations skip missing values by default.
  • dplyr filter() keeps only rows where the condition is TRUE; both FALSE and NA are removed.
  • A nullable pandas Boolean mask generally treats pd.NA as false during indexing.
  • pandas merge matches null keys to each other, unlike ordinary SQL joins. dplyr can use na_matches = "never" to disable missing-key matches.

Index alignment

A dplyr tibble has no pandas-style row index that participates in alignment. pandas assignment, arithmetic, and concat(axis=1) can align by labels and create unexpected missing values. Use reset_index(drop=True) or NumPy arrays only when positional behavior is truly intended.

Group keys and output shape

  • pandas groupby(..., as_index=True) puts keys in the index by default; this guide frequently uses as_index=False to keep regular columns.
  • dplyr summarise() returns one row per group; use reframe() for arbitrary row counts.
  • pandas agg(), transform(), filter(), and apply() have different output-shape contracts and are not interchangeable.

Side effects and copies

dplyr pipelines normally leave the source object unchanged. Assignment after chained pandas indexing can be ambiguous. Prefer .loc[...] = ... or assign(), and do not assume inplace=True provides a performance benefit.

Performance and maintainability

  1. Select required rows and columns before expensive computation or joins.
  2. Check join-key uniqueness, missingness, and expected relationship before merging.
  3. In R, prefer vectorized functions and across(); in Python, prefer Series/NumPy operations over row-wise apply().
  4. Do not repeatedly bind_rows() or pd.concat() inside a loop. Accumulate pieces and concatenate once.
  5. On large pandas frames, inspect dtypes; strings, categoricals, nullable integers, and Arrow-backed dtypes affect memory and semantics.
  6. On databases, use translatable operations and inspect SQL with show_query() or an execution plan.
  7. Write clear, testable code first, then benchmark bottlenecks on representative data.
