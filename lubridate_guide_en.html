What does this guide solve?

lubridate is the core date-time package in the tidyverse ecosystem. It makes parsing, component extraction, date arithmetic, time-zone conversion, and interval operations readable. Date-time work nevertheless remains genuinely complex: months differ in length, leap years exist, daylight saving time skips or repeats local clock times, and one instant can be displayed in many time zones.

This guide explains:

  • The inputs, outputs, and object types of lubridate functions;
  • The differences among Date, POSIXct, Duration, Period, and Interval;
  • A pandas equivalent for each common task;
  • Which time-zone operations preserve the instant and which preserve clock fields;
  • How to build testable, reproducible time-data workflows inside dplyr pipelines.

Before writing date-time code, decide whether a value is an instant, a local wall-clock reading, an exact number of seconds, or a calendar unit. Choosing the wrong object may produce code that runs while answering the wrong business question.

Parse dates with ymd(), mdy(), and dmy()

The function name expresses the order of year, month, and day in the input. Separators may vary, but the component order must not be ambiguous.

R
ymd(c("2025-08-11", "2025/08/12", "20250813"))
mdy(c("08-11-2025", "Aug 12, 2025"))
dmy(c("11/08/2025", "12 Aug 2025"))

ydm("2025-31-01")
yq(c("2025 Q1", "2025-Q4"))
ym(c("2025-01", "2025/12"))
Python
#| eval: false

pd.to_datetime(pd.Series(["2025-08-11", "2025/08/12", "20250813"]), format="mixed")
pd.to_datetime(pd.Series(["08-11-2025", "Aug 12, 2025"]), format="mixed")
pd.to_datetime(pd.Series(["11/08/2025", "12 Aug 2025"]), format="mixed", dayfirst=True)

No parser can determine from 01/02/2025 alone whether it means January 2 or February 1. Resolve the order from the data contract, source region, or schema; a parsing function cannot solve a definition problem.

Parse date-times with the ymd_hms() family

When a date includes hours, minutes, or seconds, append _hms, _hm, or _h to the function name. The tz supplied while parsing controls how the input clock fields are interpreted, not merely how output is printed.

R
ymd_hms("2025-08-11 14:30:45", tz = "UTC")
ymd_hm("2025-08-11 14:30", tz = "America/Edmonton")
mdy_hms("08/11/2025 02:30:45 PM", tz = "America/New_York")
dmy_h("11-08-2025 14", tz = "Europe/Paris")

ymd_hms("2025-08-11T14:30:45.123Z", quiet = TRUE)
Python
#| eval: false

pd.to_datetime("2025-08-11 14:30:45", utc=True)
pd.Timestamp("2025-08-11 14:30").tz_localize("America/Edmonton")
pd.to_datetime("08/11/2025 02:30:45 PM", format="%m/%d/%Y %I:%M:%S %p").tz_localize("America/New_York")
pd.to_datetime("2025-08-11T14:30:45.123Z", utc=True)

In ISO 8601, Z means UTC and an offset such as -06:00 states the offset explicitly. Offset-bearing input is safer than abbreviations such as MST or CST, which can be ambiguous.

Mixed formats with parse_date_time()

When a column truly contains a finite set of formats, use orders to state which orders are allowed. truncated accepts timestamps missing trailing components, but broadens the input domain and therefore requires documented defaults.

R
mixed <- c(
  "2025-08-11 14:30:45",
  "11/08/2025 14:30",
  "Aug 12, 2025 09:15",
  "2025-08-13"
)

parse_date_time(
  mixed,
  orders = c("Ymd HMS", "dmy HM", "b d, Y HM", "Ymd"),
  tz = "UTC"
)

parse_date_time(
  c("2025-08-11 14:30:45", "2025-08-11 14:30", "2025-08-11"),
  orders = "Ymd HMS",
  truncated = 3,
  tz = "UTC"
)

Parse failures, invalid dates, and quality audits

A parse failure normally returns NA with a warning. Production code should count failures explicitly, retain the source text, and show failed examples rather than hiding the problem with quiet = TRUE.

R
raw_dates <- c("2025-02-28", "2025-02-30", "not-a-date", NA)
parsed_dates <- ymd(raw_dates, quiet = TRUE)

tibble(raw = raw_dates, parsed = parsed_dates) |>
  mutate(failed = !is.na(raw) & is.na(parsed))

sum(!is.na(raw_dates) & is.na(parsed_dates))
unique(raw_dates[!is.na(raw_dates) & is.na(parsed_dates)])
Python
#| eval: false

raw_dates = pd.Series(["2025-02-28", "2025-02-30", "not-a-date", None])
parsed_dates = pd.to_datetime(raw_dates, errors="coerce")
audit = pd.DataFrame({"raw": raw_dates, "parsed": parsed_dates})
audit["failed"] = audit["raw"].notna() & audit["parsed"].isna()
audit.loc[audit["failed"], "raw"].unique()

Never replace a parse failure automatically with the current date. An explicit missing value is safer than a plausible-looking but false timestamp.

Unix, Excel, and other numeric timestamps

A number does not contain its own unit or origin. Unix values are commonly seconds or milliseconds since 1970-01-01 UTC. Excel dates are usually days from a particular origin, and source systems may use either the 1900 or 1904 date system.

R
unix_seconds <- c(0, 1_700_000_000)
as_datetime(unix_seconds, origin = "1970-01-01", tz = "UTC")

unix_milliseconds <- 1_700_000_000_000
as_datetime(unix_milliseconds / 1000, origin = "1970-01-01", tz = "UTC")

excel_serial <- c(1, 45292)
as_date(excel_serial, origin = "1899-12-30")
Python
#| eval: false

pd.to_datetime(pd.Series([0, 1_700_000_000]), unit="s", origin="unix", utc=True)
pd.to_datetime(pd.Series([1_700_000_000_000]), unit="ms", origin="unix", utc=True)
pd.to_datetime(pd.Series([1, 45292]), unit="D", origin="1899-12-30")

Read the data dictionary before choosing unit and origin. Guessing from magnitude can shift dates by decades when seconds, milliseconds, and microseconds are confused.

Weeks, ISO years, quarters, and fiscal periods

Near a year boundary, the year to which a week belongs may differ from the calendar year. ISO weeks start on Monday, and week 1 contains the year's first Thursday.

R

tibble(
  date = boundary,
  year = year(boundary),
  week = week(boundary),
  isoyear = isoyear(boundary),
  isoweek = isoweek(boundary),
  epiyear = epiyear(boundary),
  epiweek = epiweek(boundary),
  quarter = quarter(boundary),
  semester = semester(boundary)
)

quarter(ymd("2025-08-11"), with_year = TRUE)
quarter(ymd("2025-08-11"), fiscal_start = 4)
Python
#| eval: false

boundary = pd.Series(pd.to_datetime(["2020-12-31", "2021-01-01", "2021-01-04"]))

Modify components with setters and update()

Component setters directly replace one field; update() replaces several at once. These operations change clock fields and may create a new instant. Inspect the result around invalid dates and DST boundaries.

month(x) <- 12
mday(x) <- 20
hour(x) <- 9
x

Python

If the intent is to add one year rather than set the year field to a chosen value, use Period arithmetic. Setters and arithmetic answer different questions.

Round and bucket time

floor_date() rounds down, ceiling_date() rounds up, and round_date() uses the nearest boundary. unit may be a second, minute, hour, day, week, month, quarter, or year, and may be written as "15 minutes".

Period: civil calendar time

A Period expresses years, months, days, hours, minutes, and seconds as calendar units. days(1) means the same wall-clock time on the next day; across DST the elapsed duration may be 23 or 25 hours.

Interval: a span with real endpoints

An Interval records two instants. It can therefore produce exact seconds or calendar-relative years, months, and days based on real history. Direction follows the order of the endpoints.

R

discharge <- ymd_hms("2025-03-02 08:30:00", tz = "UTC")

stay <- interval(admission, discharge)
stay2 <- admission %--% discharge

int_start(stay)
int_end(stay)
int_length(stay)
as.duration(stay)
as.period(stay)
time_length(stay, "day")
time_length(stay, "month")

A complete cleaning workflow

The following pipeline combines parsing, auditing, UTC standardization, feature derivation, and summarization into a testable workflow.

  mutate(
    created = ymd_hms(created_text, tz = "UTC", quiet = TRUE),
    closed = ymd_hms(closed_text, tz = "UTC", quiet = TRUE),
    created_failed = !is.na(created_text) & is.na(created),
    closed_failed = !is.na(closed_text) & is.na(closed),
    impossible_order = !is.na(closed) & closed < created,
    month = floor_date(created, "month"),
    iso_year = isoyear(created),
    iso_week = isoweek(created),
    elapsed = as.duration(created %--% closed),
    elapsed_hours = as.numeric(elapsed, units = "hours")
  )

quality_report <- clean_events |>
  summarise(
    rows = n(),
    created_parse_failures = sum(created_failed),
    closed_parse_failures = sum(closed_failed),
    reversed_intervals = sum(impossible_order, na.rm = TRUE),
    missing_closed = sum(is.na(closed))
  )

report <- clean_events |>
  filter(!created_failed, !closed_failed, !impossible_order) |>
  summarise(
    events = n(),
    completed = sum(!is.na(closed)),
    median_hours = median(elapsed_hours, na.rm = TRUE),
    p90_hours = quantile(elapsed_hours, 0.90, na.rm = TRUE),

Performance, maintainability, and testing

  1. State a format when input is fixed so each batch does not guess again.
  2. Evaluate parse_date_time2() or fast_strptime() for large vectors, but verify invalid and DST behavior first.
  3. Standardize internal instants to UTC and keep original text, source zone, and parse status.
  4. Use temporal types for join and group keys; convert to strings only in the presentation layer.
  5. Test leap days, month ends, year ends, ISO week 1, DST gaps/folds, and missing values.
  6. Do not call now() deep inside functions; pass as_of as an argument.
  7. Record package version, time-zone database, locale, and business-calendar version.
  8. Prefer vectorization for large tables; when zones differ by row, convert by zone group where possible.
