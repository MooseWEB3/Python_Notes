How to Use This Tutorial

This is a practical guide for people who are new to Python data processing. The goal is not to memorize functions. It is to build a dependable workflow:

  1. Load the data;
  2. Understand the data;
  3. Clean problems;
  4. Transform and calculate;
  5. Aggregate or combine;
  6. Validate the result;
  7. Export the data.

Most examples use pandas, with NumPy where it is helpful. Code blocks are displayed but are not executed while the HTML is generated, so the rendering computer does not need Python packages. Copy the examples into Jupyter Notebook, VS Code, or a Python script to run them.

The most important beginner habit is to check row counts, column names, data types, missing values, and a few sample rows after every major step.

Learning Goals

After completing this tutorial, you should be able to:

  • Process small collections with Python containers;
  • Read CSV, Excel, and JSON files with pandas;
  • Inspect, select, filter, sort, and modify tabular data;
  • Handle missing values, duplicates, text, dates, and incorrect types;
  • Use grouping, aggregation, joins, and pivot tables;
  • Export tidy data and perform basic quality checks;
  • Complete a small sales-data processing project independently.

1. Environment and Core Ideas

1.1 Install Common Packages

Run this command in a terminal:

python -m pip install pandas numpy openpyxl jupyter

Then import the packages in Python:

import numpy as np
import pandas as pd

print(pd.__version__)
  • pandas: works with tabular data;
  • numpy: provides efficient numerical operations;
  • openpyxl: lets pandas read and write .xlsx files;
  • jupyter: provides an interactive environment for code and results.

1.2 Series and DataFrame

A Series is similar to one labeled column. A DataFrame is a two-dimensional table made of multiple columns.

scores = pd.Series([88, 92, 79], name="score")

students = pd.DataFrame({
    "name": ["Amy", "Ben", "Chen"],
    "score": [88, 92, 79]
})

A DataFrame has two important axes:

  • axis=0: the row direction, often used for vertical concatenation;
  • axis=1: the column direction, often used for horizontal concatenation.

2. Basic Processing Without pandas

For very small datasets, Python’s built-in lists, dictionaries, and sets may be enough.

2.1 List Comprehensions

prices = [18.5, 12.0, 899.0, 350.0]

expensive = [price for price in prices if price >= 100]
with_tax = [round(price * 1.05, 2) for price in prices]

The general structure is:

[value_to_create for temporary_variable in iterable if condition]

2.2 Dictionaries and Safe Lookup

record = {"name": "Alice", "city": "Calgary"}

name = record["name"]                 # raises an error if the key is absent
age = record.get("age", "Unknown")   # returns a default if the key is absent

2.3 Removing Duplicates with Sets

cities = ["Calgary", "Toronto", "Calgary", "Edmonton"]
unique_cities = set(cities)

Sets are unordered. To remove duplicates while preserving the original order:

unique_in_order = list(dict.fromkeys(cities))

When data grows to hundreds or thousands of structured rows, or when you need grouping and joins, pandas is usually the better tool.

3. Reading and Saving Data

3.1 CSV

df = pd.read_csv("data/orders.csv")

Useful options include:

df = pd.read_csv(
    "data/orders.csv",
    encoding="utf-8",
    na_values=["", "NA", "N/A", "null", "-"],
    usecols=["order_id", "customer", "order_date", "quantity", "unit_price"],
    dtype={"order_id": "string"}
)

If non-English characters look corrupted, confirm the source file’s actual encoding. Older files exported on Windows may require encoding="gbk", encoding="gb18030", or another regional encoding. Do not ignore damaged characters after randomly trying encodings.

3.2 Excel

sales = pd.read_excel("data/sales.xlsx", sheet_name="Orders")

# Read every sheet and return {sheet_name: DataFrame}
all_sheets = pd.read_excel("data/sales.xlsx", sheet_name=None)

Common Excel problems include merged cells, headers below the first row, and mixed numbers and text in one column:

sales = pd.read_excel(
    "data/sales.xlsx",
    sheet_name="Orders",
    header=2,       # use the third row as column names
    usecols="A:H"
)

3.3 JSON

df = pd.read_json("data/orders.json")

Use json_normalize to flatten nested JSON:

import json

with open("data/customers.json", encoding="utf-8") as file:
    raw = json.load(file)

customers = pd.json_normalize(raw, sep="_")

3.4 File Paths

Use pathlib instead of manually joining slash characters:

from pathlib import Path

project_dir = Path.cwd()
input_file = project_dir / "data" / "orders.csv"
output_file = project_dir / "output" / "clean_orders.csv"

output_file.parent.mkdir(parents=True, exist_ok=True)

3.5 Exporting

orders.to_csv("output/clean_orders.csv", index=False, encoding="utf-8-sig")
orders.to_excel("output/clean_orders.xlsx", index=False)
orders.to_json("output/clean_orders.json", orient="records", force_ascii=False, indent=2)

index=False prevents the DataFrame index from becoming an unwanted output column. utf-8-sig often improves compatibility between non-English CSV files and Excel.

4. Quickly Understanding a Dataset

Do not start calculations immediately after receiving a new dataset. First ask: How many rows and columns are present? What are the names and types? Where are values missing?

orders.shape          # (number_of_rows, number_of_columns)
orders.columns        # all column names
orders.dtypes         # type of each column
orders.head()         # first 5 rows
orders.tail(3)        # last 3 rows
orders.sample(3, random_state=42)  # reproducible random sample
orders.info()         # types, non-null counts, and memory information

Numerical summary:

orders.describe()

Summary including text columns:

orders.describe(include="all")

Category frequencies and missing values:

orders["status"].value_counts(dropna=False)
orders.isna().sum().sort_values(ascending=False)
orders.nunique(dropna=False)

After every import, record three things: shape, dtypes, and the number of missing values in each column. They are invaluable when a later result looks wrong.

5. Selecting, Filtering, and Sorting

5.1 Selecting Columns

orders["customer"]                          # returns a Series
orders[["customer", "city", "status"]]    # returns a DataFrame

One pair of brackets selects one column. Multiple columns require a list of column names, which creates the second pair of brackets.

5.2 Label-Based Selection with loc

orders.loc[0:2, ["order_id", "customer"]]

A loc row slice normally includes the ending label, so 0:2 includes index 2.

5.3 Position-Based Selection with iloc

orders.iloc[0:3, 0:2]

iloc follows normal Python slicing and excludes the ending position. Therefore, 0:3 selects rows 0, 1, and 2.

5.4 Conditional Filtering

book_orders = orders[orders["category"] == "Book"]

large_paid = orders[
    (orders["quantity"] >= 2) &
    (orders["status"].str.strip().str.lower() == "paid")
]

Use these operators for multiple conditions:

  • & means AND;
  • | means OR;
  • ~ means NOT;
  • Put parentheses around each condition.

Do not use the regular Python and or or operators between Series conditions.

Other useful filters:

orders[orders["city"].isin(["Calgary", "Edmonton"])]
orders[orders["unit_price"].between(10, 100, inclusive="both")]
orders[orders["customer"].str.contains("a", case=False, na=False)]

5.5 Sorting

orders.sort_values("unit_price", ascending=False)

orders.sort_values(
    ["city", "unit_price"],
    ascending=[True, False],
    na_position="last"
)

Most pandas methods return a new DataFrame. Assign the result if you want to keep it:

orders = orders.sort_values("order_id").reset_index(drop=True)

6. Cleaning Data

6.1 Standardize Column Names

orders.columns = (
    orders.columns
    .str.strip()
    .str.lower()
    .str.replace(" ", "_", regex=False)
)

You can also rename specific columns:

orders = orders.rename(columns={"order_date": "date"})

6.2 Missing Values

First identify missing values:

orders.isna().sum()
orders[orders["quantity"].isna()]

An empty string is not automatically treated as missing. Convert it explicitly:

orders["customer"] = orders["customer"].replace(r"^\s*$", pd.NA, regex=True)

Common treatments:

# Remove rows missing a critical field
valid_orders = orders.dropna(subset=["order_id"])

# Fill missing values
orders["customer"] = orders["customer"].fillna("Unknown")
orders["quantity"] = orders["quantity"].fillna(0)

# Example: fill with the median from the same group
orders["unit_price"] = orders["unit_price"].fillna(
    orders.groupby("category")["unit_price"].transform("median")
)

Missing does not mean zero. Fill with zero only when the business meaning supports it. A missing discount may mean no discount; a missing age usually does not mean age zero.

6.3 Duplicate Values

orders.duplicated().sum()
orders[orders.duplicated(keep=False)]

orders = orders.drop_duplicates()
orders = orders.drop_duplicates(subset=["order_id"], keep="last")

Before deduplicating by order_id, decide whether to keep the first record, the last record, or the record with the newest update timestamp.

6.4 Converting Data Types

orders["quantity"] = pd.to_numeric(orders["quantity"], errors="coerce")
orders["unit_price"] = pd.to_numeric(orders["unit_price"], errors="coerce")
orders["order_date"] = pd.to_datetime(orders["order_date"], errors="coerce")

orders["quantity"] = orders["quantity"].fillna(0).astype("int64")
orders["category"] = orders["category"].astype("category")

errors="coerce" converts invalid values to missing values so you can inspect them consistently:

bad_dates = orders[orders["order_date"].isna()]

6.5 Cleaning Text

orders["status"] = (
    orders["status"]
    .astype("string")
    .str.strip()
    .str.lower()
    .replace({"cancelled": "canceled"})
)

orders["city"] = orders["city"].str.strip().str.title()

Useful string methods:

orders["customer"].str.len()
orders["customer"].str.startswith("A", na=False)
orders["customer"].str.replace(r"\s+", " ", regex=True)
orders["customer"].str.split(" ", expand=True)

6.6 Outliers and Valid Ranges

Business-rule checks are often easier to explain than complex algorithms:

invalid = orders[
    (orders["quantity"] < 0) |
    (orders["unit_price"] < 0) |
    (~orders["discount"].between(0, 1, inclusive="both"))
]

Use the interquartile range (IQR) to find statistical outliers:

q1 = orders["unit_price"].quantile(0.25)
q3 = orders["unit_price"].quantile(0.75)
iqr = q3 - q1

lower = q1 - 1.5 * iqr
upper = q3 + 1.5 * iqr
outliers = orders[~orders["unit_price"].between(lower, upper)]

An outlier is not automatically an error. An expensive product may be genuine. Flag and investigate outliers before deciding to remove them.

7. Creating and Transforming Columns

7.1 Vectorized Calculations

orders["discount"] = orders["discount"].fillna(0).clip(0, 1)
orders["gross"] = orders["quantity"] * orders["unit_price"]
orders["net_sales"] = orders["gross"] * (1 - orders["discount"])
orders["net_sales"] = orders["net_sales"].round(2)

These whole-column operations are called vectorized operations. They are usually shorter and faster than row-by-row loops.

7.2 Conditional Columns

orders["size"] = np.where(orders["net_sales"] >= 100, "large", "small")

Use np.select for multiple conditions:

conditions = [
    orders["net_sales"] >= 500,
    orders["net_sales"] >= 100
]
choices = ["high", "medium"]

orders["sales_band"] = np.select(conditions, choices, default="low")

7.3 Mapping Values

city_region = {
    "Calgary": "West",
    "Edmonton": "West",
    "Vancouver": "West",
    "Toronto": "East"
}

orders["region"] = orders["city"].map(city_region).fillna("Other")

7.4 apply: Use It When Needed

def shipping_fee(row):
    if row["city"] == "Calgary":
        return 0
    if row["net_sales"] >= 200:
        return 0
    return 15

orders["shipping_fee"] = orders.apply(shipping_fee, axis=1)

apply(axis=1) is intuitive but can be slow on large datasets. Prefer whole-column operations, map, where, or np.select when possible.

7.5 Method Chaining and assign

paid_orders = (
    orders
    .assign(
        gross=lambda x: x["quantity"] * x["unit_price"],
        net_sales=lambda x: x["gross"] * (1 - x["discount"].fillna(0))
    )
    .query("status == 'paid'")
    .sort_values("net_sales", ascending=False)
)

Method chains can express a workflow clearly, but very long chains are difficult to debug. Beginners can split a workflow into a few meaningfully named intermediate variables.

8. Dates and Times

orders["order_date"] = pd.to_datetime(orders["order_date"], errors="coerce")

orders["year"] = orders["order_date"].dt.year
orders["month"] = orders["order_date"].dt.to_period("M").astype("string")
orders["weekday"] = orders["order_date"].dt.day_name()
orders["days_since_order"] = pd.Timestamp.today().normalize() - orders["order_date"]

Filter a date range:

february = orders[orders["order_date"].between("2026-02-01", "2026-02-28")]

Monthly resampling requires a date index:

monthly = (
    orders
    .set_index("order_date")
    .resample("MS")["net_sales"]
    .sum()
)

Real projects must also consider time zones. For time-zone-aware data:

events["timestamp"] = pd.to_datetime(events["timestamp"], utc=True)
events["local_time"] = events["timestamp"].dt.tz_convert("America/Edmonton")

9. Grouping and Aggregation

9.1 One Aggregation

sales_by_city = orders.groupby("city")["net_sales"].sum()

9.2 Multiple Aggregations

summary = (
    orders
    .groupby("city", as_index=False)
    .agg(
        order_count=("order_id", "nunique"),
        total_quantity=("quantity", "sum"),
        total_sales=("net_sales", "sum"),
        average_order=("net_sales", "mean")
    )
    .sort_values("total_sales", ascending=False)
)

Common aggregation functions include sum, mean, median, min, max, count, size, and nunique.

  • count: counts non-missing values;
  • size: counts all rows in a group, including rows containing missing values;
  • nunique: counts distinct values.

9.3 The Difference Between agg and transform

agg reduces the number of rows, usually to one row per group. transform returns a result with the same number of rows as the original data.

orders["city_average"] = (
    orders.groupby("city")["net_sales"].transform("mean")
)

orders["vs_city_average"] = orders["net_sales"] - orders["city_average"]

10. Joining and Concatenating

10.1 merge: Join on Keys

customers = pd.DataFrame({
    "customer": ["Alice", "Bob", "Chen", "Diana"],
    "segment": ["Retail", "Retail", "Business", "Business"]
})

enriched = orders.merge(
    customers,
    on="customer",
    how="left",
    validate="many_to_one",
    indicator=True
)

Join types:

how Meaning
left Keep every row from the left table
right Keep every row from the right table
inner Keep only rows matched in both tables
outer Keep all rows and use missing values for unmatched fields

validate="many_to_one" says that the left table may contain a customer many times, but the customer key in the right table must be unique. This prevents an accidental many-to-many join from multiplying rows.

Check matching status:

enriched["_merge"].value_counts()
unmatched = enriched[enriched["_merge"] == "left_only"]

10.2 concat: Stack or Align Tables

all_orders = pd.concat([january_orders, february_orders], ignore_index=True)

side_by_side = pd.concat([customer_info, customer_scores], axis=1)

Before vertical concatenation, check that column names and types agree. Horizontal concatenation aligns by index; inconsistent indexes can create unexpected missing values.

11. Reshaping Wide and Long Data

11.1 Pivot Tables

pivot = pd.pivot_table(
    orders,
    index="city",
    columns="category",
    values="net_sales",
    aggfunc="sum",
    fill_value=0,
    margins=True
)

11.2 Long to Wide

When each city-and-category combination is unique, use pivot:

wide = monthly_sales.pivot(
    index="month",
    columns="category",
    values="sales"
)

If a combination is not unique, pivot raises an error. Use pivot_table, which can aggregate repeated combinations.

11.3 Wide to Long

long = wide.reset_index().melt(
    id_vars="month",
    var_name="category",
    value_name="sales"
)

Long data is usually better for grouping, plotting, and statistical models. Wide data is often easier for people to read and for some report formats.

12. Indexes, Copies, and Common Traps

12.1 An Index Is Not a Regular Column

orders = orders.set_index("order_id")
orders = orders.reset_index()

Indexes are useful for label lookup and time series. Before exporting or joining, decide whether an index should become a regular column.

12.2 Avoid Chained Assignment

Not recommended:

orders[orders["city"] == "Calgary"]["region"] = "West"

Recommended:

orders.loc[orders["city"] == "Calgary", "region"] = "West"

Explicitly copy a subset when you want it to be independent:

calgary = orders.loc[orders["city"] == "Calgary"].copy()

12.3 Do Not Accidentally Overwrite Raw Data

Keep the source data and clean a copy:

raw_orders = pd.read_csv("data/orders.csv")
orders = raw_orders.copy()

12.4 Check Row Counts After Joins

before_rows = len(orders)
enriched = orders.merge(customers, on="customer", how="left", validate="many_to_one")
after_rows = len(enriched)

assert before_rows == after_rows

13. Large Data and Performance

Write correct and understandable code first, then optimize. Common improvements include:

  • Use usecols to load only required columns;
  • Specify appropriate dtype values;
  • Prefer vectorized operations;
  • Avoid repeatedly appending rows to a DataFrame inside a loop;
  • Consider the category type for text columns with many repeated values;
  • Process very large CSV files in chunks.

Chunking example:

totals = []

for chunk in pd.read_csv("data/large_orders.csv", chunksize=100_000):
    chunk["sales"] = chunk["quantity"] * chunk["unit_price"]
    totals.append(chunk.groupby("city")["sales"].sum())

city_totals = pd.concat(totals, axis=1).sum(axis=1)

14. Data Quality Checks

Perform at least these checks when processing is complete:

assert orders["order_id"].notna().all(), "order_id must not be missing"
assert orders["order_id"].is_unique, "order_id must be unique"
assert orders["quantity"].ge(0).all(), "quantity must not be negative"
assert orders["discount"].between(0, 1).all(), "discount must be between 0 and 1"
assert orders["status"].isin(["paid", "refunded", "canceled"]).all()

You can also record row counts before and after processing:

quality_report = {
    "rows": len(orders),
    "columns": orders.shape[1],
    "missing_cells": int(orders.isna().sum().sum()),
    "duplicate_order_ids": int(orders["order_id"].duplicated().sum())
}

print(quality_report)

A failed assertion is useful: it stops incorrect results before they reach a report.

15. Complete Mini-Project: Clean and Summarize Orders

The following example combines the earlier methods into one complete workflow.

import numpy as np
import pandas as pd

# 1. Copy the source to protect the original object
clean = orders.copy()

# 2. Standardize column names
clean.columns = (
    clean.columns.str.strip().str.lower().str.replace(" ", "_", regex=False)
)

# 3. Clean text and missing values
clean["customer"] = clean["customer"].replace(r"^\s*$", pd.NA, regex=True)
clean["customer"] = clean["customer"].fillna("Unknown")
clean["status"] = (
    clean["status"]
    .astype("string")
    .str.strip()
    .str.lower()
    .replace({"cancelled": "canceled"})
)

# 4. Convert types
clean["quantity"] = pd.to_numeric(clean["quantity"], errors="coerce").fillna(0)
clean["quantity"] = clean["quantity"].astype("int64")
clean["unit_price"] = pd.to_numeric(clean["unit_price"], errors="coerce")
clean["discount"] = pd.to_numeric(clean["discount"], errors="coerce").fillna(0)
clean["discount"] = clean["discount"].clip(0, 1)
clean["order_date"] = pd.to_datetime(clean["order_date"], errors="coerce")

# 5. Remove fully duplicated rows and check order keys
clean = clean.drop_duplicates()
assert clean["order_id"].notna().all()
assert clean["order_id"].is_unique

# 6. Create calculated columns
clean["gross"] = clean["quantity"] * clean["unit_price"]
clean["net_sales"] = (clean["gross"] * (1 - clean["discount"])).round(2)
clean["month"] = clean["order_date"].dt.to_period("M").astype("string")

# 7. Keep only paid orders for the revenue report
paid = clean.loc[clean["status"] == "paid"].copy()

monthly_summary = (
    paid
    .groupby("month", as_index=False, dropna=False)
    .agg(
        orders=("order_id", "nunique"),
        customers=("customer", "nunique"),
        revenue=("net_sales", "sum")
    )
    .sort_values("month")
)

customer_ranking = (
    paid
    .groupby("customer", as_index=False)
    .agg(revenue=("net_sales", "sum"))
    .sort_values("revenue", ascending=False)
)

# 8. Final quality checks
assert paid["status"].eq("paid").all()
assert paid["net_sales"].ge(0).all()
assert round(paid["net_sales"].sum(), 2) == 662.90

# 9. Export the outputs
clean.to_csv("clean_orders.csv", index=False, encoding="utf-8-sig")
monthly_summary.to_csv("monthly_summary.csv", index=False, encoding="utf-8-sig")
customer_ranking.to_csv("customer_ranking.csv", index=False, encoding="utf-8-sig")

print(monthly_summary)
print(customer_ranking)

Expected monthly result:

month orders customers revenue
2026-01 3 2 87.90
2026-02 3 3 575.00

This project demonstrates an important principle: cleaning rules, business filters, and quality checks should live in the code rather than only in the operator’s memory.

18. What to Learn Next

A useful learning order is:

  1. Run and modify every example in this tutorial in Jupyter;
  2. Repeat the complete workflow with a real CSV file;
  3. Learn basic visualization with matplotlib or seaborn;
  4. Learn functions, modules, exception handling, and logging;
  5. When data volume or collaboration needs grow, explore SQL, Parquet, Polars, or PySpark.

Do not try to memorize every API at once. First become comfortable with the main sequence—load, inspect, clean, transform, summarize, validate, and export—then expand your toolbox gradually.
