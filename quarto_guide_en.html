Before you start: what is Quarto?

Quarto is an open-source publishing system for scientific computing and technical communication. A useful mental model is a modern, cross-language continuation of the R Markdown idea: prose is written in Pandoc Markdown, computations run through engines such as knitr or Jupyter, and the same source can produce HTML, PDF, Word, presentations, websites, and books.

Quarto is more than a new extension for R Markdown. It brings output formats, cross-references, websites, books, presentations, themes, and publishing into one consistent system.

NeedRecommended choice
Maintain an existing R Markdown reportKeep .Rmd and render it with Quarto
Start an R-first reportPrefer .qmd + knitr
Start a Python-first reportUse .qmd + Jupyter
Mix R and Python in one documentUse knitr + reticulate, or split the work
Build a documentation site or bookUse a Quarto project

This tutorial uses .Rmd as requested, so it is also a migration example. Quarto can render most existing .Rmd documents. For new work, .qmd is usually preferred because it clearly identifies the file as a Quarto document.

Installation and environment checks

Install the components

At minimum:

  1. Install the Quarto CLI.
  2. For R, install R and the rmarkdown package; it brings in knitr and related dependencies.
  3. For Python, install Python, Jupyter, and the scientific packages your analysis needs.
  4. Use RStudio, Positron, VS Code, or any text editor.
R
install.packages(c("rmarkdown", "quarto", "reticulate"))
Terminal
python -m pip install jupyter matplotlib pandas

Verify from a terminal

Terminal
quarto --version
quarto check
Rscript --version
python --version

quarto check summarizes Quarto, Pandoc, browser, LaTeX, R, and Python/Jupyter discovery. It is the best first command when a render environment is not behaving as expected.

Your first HTML document in five minutes

Create hello.qmd:

Markdown
---
title: "My first Quarto report"
format:
  html:
    toc: true
    code-fold: true
---

## Summary

Ordinary Markdown, math such as $y = \alpha + \beta x$, and executable code can live together.

```{r}
#| label: fig-cars
#| fig-cap: "Speed and stopping distance"

plot(cars, pch = 19, col = "#2c7fb8")
```

In that directory, run:

Terminal
quarto render hello.qmd

During development, use:

Terminal
quarto preview hello.qmd

preview starts a local server and refreshes as you edit. render is appropriate for final output and automated builds.

YAML: the document control panel

The content between the opening --- lines is YAML metadata. Use spaces, never tabs, and keep indentation consistent.

YAML
---
title: "Quarterly analysis"
subtitle: "Sales, margin, and risk"
author:
  - name: "Analytics team"
date: today
lang: en
format:
  html:
    toc: true
    toc-depth: 3
    number-sections: true
    code-fold: true
    code-copy: true
    theme: cosmo
    embed-resources: true
execute:
  echo: true
  warning: false
  message: false
---

Frequently used options:

OptionPurpose
toc / toc-depthShow a table of contents and control its depth
number-sectionsNumber sections automatically
code-foldCollapse source code while retaining output
code-copyAdd a copy button to code blocks
embed-resourcesPut CSS, JavaScript, and images into one HTML file
themeSelect a Bootstrap theme or custom SCSS
executeSet document-wide computation defaults

embed-resources: true is useful for an HTML file that must work offline or travel by email. For a large site, separate assets are usually more efficient.

Callouts

Markdown

## Warning

Never put passwords, access tokens, or real customer data in source files or rendered HTML.
:::

Available callout types include note, tip, warning, caution, and important.

Tabsets

Footnotes, citations, and cross-references

Write a footnote as This is a claim.^[This is the supporting note.].

Give figures, tables, equations, and sections stable labels:

Markdown
As @fig-trend shows, the series generally rises.

```{r}
#| label: fig-trend
#| fig-cap: "Monthly trend"

plot(1:12, cumsum(c(3, -1, 4, 2, 1, 5, -2, 3, 2, 4, 1, 3)), type = "b")
```

$$
y_i = \alpha + \beta x_i + \epsilon_i
$$ {#eq-model}

The model is defined in @eq-model.

Labels use reserved prefixes such as fig-, tbl-, eq-, and sec-. Prefer hyphens and avoid underscores.

Citations usually use bibliography: references.bib in YAML and [@key] in the body. Quarto uses Pandoc citation processing and can apply a CSL style file.

Using R: the knitr workflow

Quarto uses knitr when it encounters R cells. That is why most .Rmd files migrate with little or no change.

R
#| label: tbl-airquality
#| tbl-cap: "First six rows of the airquality data"

knitr::kable(head(airquality))

Cell options

Quarto recommends #| option comments at the top of a cell:

Markdown
```{r}
#| label: fig-pressure
#| fig-cap: "Temperature and pressure"
#| fig-width: 7
#| fig-height: 4
#| echo: true
#| warning: false

plot(pressure, type = "b", pch = 19)
```

Common execution options:

OptionTypical valuesMeaning
echotrue / falseShow the source code
evaltrue / falseExecute the cell
outputtrue / false / asisInclude or interpret output
includetrue / falseInclude both source and output
warning / messagetrue / falseShow warnings and messages
errortrue / falseContinue after an execution error

Inline R

In a knitr document, an inline expression can place a computed value in a sentence, for example `r mean(c(2, 4, 8))` . This is excellent for dates, sample sizes, and key metrics, but avoid expensive work inline.

Using Python

Recommended for new projects: Jupyter

In a Python-focused .qmd, Quarto normally uses Jupyter:

Markdown
---
title: "Python analysis"
jupyter: python3
format: html
---

```{python}
#| label: fig-python
#| fig-cap: "A trend generated with Python"

import matplotlib.pyplot as plt

x = list(range(1, 7))
y = [3, 5, 4, 8, 9, 12]
plt.plot(x, y, marker="o")
plt.show()
```

Running Python in an .Rmd

This tutorial is on the knitr path. In a knitr document, Python chunks are normally provided by reticulate:

Markdown
```{python}
#| eval: false

values = [3, 5, 4, 8, 9, 12]
sum(values) / len(values)
```

Select and inspect Python from R:

R
library(reticulate)
use_python("/path/to/python", required = TRUE)
py_config()

Prefer a virtual environment, and select it before Python is initialized for the session. On Windows, C:/path/to/python.exe avoids backslash escaping problems.

Mixing R and Python: boundaries and good patterns

“Quarto supports both R and Python” means that Quarto integrates computation engines such as knitr and Jupyter. It does not mean one document automatically dispatches arbitrary cells to several independent engines.

For mixed-language work in one .Rmd / knitr document, a common pattern is:

  1. R is the host session.
  2. reticulate starts and manages embedded Python.
  3. Python reads R objects through r.object_name.
  4. R reads Python objects through py$object_name.
Markdown
```{r}
r_sales <- data.frame(month = 1:3, amount = c(10, 14, 18))
```

```{python}
#| eval: false

py_sales = r.r_sales
py_total = py_sales["amount"].sum()
```

```{r}
# After the Python cell has run: py$py_total
```

Cross-language conversion can change categorical data, dates, missing values, and indexes. For large data, prefer Parquet/Arrow, a database, or an explicit intermediate file, and assert the resulting types.

If the R and Python parts are independent, two source documents joined by project navigation are often more reliable than forcing them to share a session.

Reproducible execution: caching, freezing, and dependencies

cache and freeze solve different problems

  • cache: true caches cell results. A change to cell source or relevant options can invalidate the cache.
  • freeze: auto is mainly project-oriented: it reuses previous computational output when a source document has not changed.

Project example:

YAML
project:
  type: website

execute:
  freeze: auto
  cache: true

Caching is not dependency management. For real reproducibility:

  • use renv to lock R packages;
  • use venv or Conda and commit a requirements.txt or lock file for Python;
  • fix random seeds;
  • record data sources, retrieval dates, and cleaning rules;
  • avoid hard-coded absolute paths.
R
set.seed(20260811)
sample(1:100, 5)

Parameterized reports

A knitr document can declare parameters in YAML:

YAML
params:
  region: "West"
  report_date: "2026-08-11"

Use them from R:

R
selected_region <- params$region
as_of <- as.Date(params$report_date)

The R package provides a convenient wrapper around the Quarto CLI:

R
quarto::quarto_render(
  "sales_report.Rmd",
  execute_params = list(region = "North")
)

Parameters are configuration, not secret storage. Keep credentials in environment variables or a secret manager, and ensure logs and HTML do not expose them.

Growing from one file into a project

A typical directory:

Text
sales-report/
├─ _quarto.yml
├─ index.qmd
├─ analysis.Rmd
├─ references.bib
├─ data/
├─ R/
├─ notebooks/
└─ styles.scss

Put shared settings in _quarto.yml:

YAML
project:
  type: website
  output-dir: _site

website:
  title: "Analytics hub"
  navbar:
    left:
      - href: index.qmd
        text: Home
      - href: analysis.Rmd
        text: Analysis

format:
  html:
    theme: cosmo
    toc: true
    code-copy: true

execute:
  freeze: auto

Common project types:

Typeproject.typeBest for
DefaultdefaultSeveral reports with shared settings
WebsitewebsiteDocumentation, blogs, research sites
BookbookCourse notes, manuals, long reports

A presentation is an output format rather than a project type. Use format: revealjs to create an HTML slide deck.

Rendering, previewing, and automation

Terminal
# One document
quarto render report.Rmd

# An explicit format
quarto render report.Rmd --to html

# The whole project
quarto render

# Live preview
quarto preview

# Remove project-generated content
quarto clean

For continuous integration:

  1. Install a fixed or controlled Quarto version.
  2. Restore R and Python dependencies.
  3. Run data validation and tests.
  4. Run quarto render.
  5. Deploy _site/ or preserve the target HTML as a build artifact.

“It renders on my machine” is not a completion criterion. Test at least once in a clean environment.

Publishing and sharing HTML

A standalone HTML file can be placed on any static server. Quarto also supports commands such as:

Terminal
quarto publish quarto-pub report.qmd
quarto publish gh-pages
quarto publish netlify

Before publishing, check that:

  • every link and cross-reference resolves;
  • no local absolute path remains;
  • no token, username, internal server name, or sensitive raw data is present;
  • charts have titles, units, and alternative text;
  • tables and code remain usable at mobile widths;
  • embed-resources: true is enabled for a standalone file, or the asset directory is deployed with it.

Migrating from R Markdown

A low-risk migration path

  1. Keep the .Rmd unchanged and run quarto render old-report.Rmd.
  2. Fix YAML validation, extension, and custom-template issues.
  3. Gradually replace old chunk options with #| syntax.
  4. Replace custom workarounds with native Quarto cross-references, callouts, and project settings.
  5. Use .qmd for new files; do not rewrite stable old files merely for the extension.

Common mappings

R MarkdownQuarto
output: html_documentformat: html
output: pdf_documentformat: pdf
html_document: toc: trueformat: html: toc: true
bookdown cross-referencesNative @fig- / @tbl- / @eq- references
flexdashboard / custom layoutQuarto dashboards or page layout
rmarkdown::render()quarto render or quarto::quarto_render()

Quarto project YAML is not wholly parsed by R, so do not assume every dynamic R expression from R Markdown YAML will work unchanged. Put dynamic values in execution or parameters where possible.

Troubleshooting

R or Python is not found

Start with quarto check. Quarto normally discovers runtimes through PATH. If necessary, configure QUARTO_R; for Python, verify the Jupyter kernel or inspect reticulate::py_config().

YAML fails to parse

  • Check for tabs.
  • Check that a space follows each colon.
  • Quote values containing colons, #, or special characters.
  • Reduce to minimal YAML and add settings back one at a time.

A code block does not execute

  • Executable cells must use {r} or {python} , not highlighting-only fences such as r `.
  • Check eval: false, include: false, and project defaults.
  • Confirm that the intended computation engine is selected.

Results are stale

Clear or refresh the cache and check external inputs. A cache does not normally know that a database changed when your source code did not. Give external inputs explicit versions or dependency hashes.

PDF fails while HTML works

PDF also needs LaTeX. TinyTeX is a practical option. Check fonts, Unicode, wide tables, and LaTeX packages. Stabilize the HTML workflow first, then troubleshoot the typesetting toolchain separately.

Recommended working habits

  1. Default to .qmd for new work and migrate old .Rmd files gradually.
  2. Treat raw data as read-only and write cleaned data elsewhere.
  3. Put functions in R/ or Python modules instead of turning the document into one giant script.
  4. Give every figure, table, and important section a stable semantic label.
  5. Hide noise in the final report, but not transformations that affect the conclusion.
  6. Use Git, and ignore caches, temporary files, and local secret-bearing configuration.
  7. Render the entire project regularly in CI or another clean environment.
  8. Include accessibility, security, and data licensing in the publication checklist.
