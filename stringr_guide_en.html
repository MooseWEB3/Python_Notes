What this guide teaches

stringr is the core tidyverse package for string manipulation. Built on stringi and the ICU Unicode library, it provides a consistent, composable, and vectorized interface. Python has no single exact counterpart:

  • use built-in str methods for one string;
  • use the standard-library re module for regular expressions;
  • use pandas Series.str for a column of strings;
  • use an ICU binding such as PyICU when language-specific collation is essential.

This guide targets the stringr 1.6 family. It explains output shape, missing values, indexes, Unicode, regex engines, and semantic differences rather than merely listing function names.

Five core differences

  1. Most stringr functions operate on character vectors. A Python str method handles one string; a column needs Series.str.
  2. str_sub() uses one-based positions with an inclusive end. Python slicing is zero-based with an exclusive stop.
  3. stringr regular expressions use stringi/ICU. Python re is similar, but Unicode properties, named groups, and some advanced constructs differ.
  4. stringr generally preserves input length and propagates NA. pandas may use pd.NA, NaN, or None depending on dtype.
  5. stringr exposes locale explicitly. Python's built-in methods do not reproduce ICU language-specific comparison and sorting.

str_width() estimates width in a monospaced display, where an East Asian wide character may occupy two cells.

def display_width(value):
    return sum(2 if unicodedata.east_asian_width(ch) in {"W", "F"} else 1 for ch in value)

Programming name styles: camel, snake, and kebab

The Python standard library has no one-function equivalent:

Python
#| eval: false

def words_in_name(value):
    value = re.sub(r"([a-z0-9])([A-Z])", r"\1 \2", value)
    return [part.lower() for part in re.split(r"[-_\s]+", value) if part]

def to_snake(value):
    return "_".join(words_in_name(value))

def to_kebab(value):
    return "-".join(words_in_name(value))

def to_camel(value):
    parts = words_in_name(value)
    return parts[0] + "".join(part.title() for part in parts[1:])

to_snake("MyVariable"), to_kebab("MyVariable"), to_camel("my-variable")

Real names contain acronyms, digits, and Unicode. Establish a team rule and lock examples into tests.

A regular-expression mental model

stringr interprets a bare pattern as an ICU regular expression. Python uses its own re engine. Their common core includes:

GoalRegex
Any non-newline character.
Digit / non-digit\d / \D
Whitespace / non-whitespace\s / \S
Word character\w
Start / end^ / $
Zero or one?
Zero or more*
One or more+
Exact/ranged count{n} / {n,m}
Capturing/non-capturing group(...) / (?:...)
Alternation`AB`

R strings and regex both use backslashes, so a digit pattern is written "\\d+". Python raw strings make the same regex r"\d+".

SQL wildcards: str_like() and str_ilike()

R
fruit <- c("apple", "banana", "pear", "pineapple")

str_like(fruit, "app%")
str_like(fruit, "ba_ana")
str_ilike(fruit, "APP%")

In SQL-style patterns, % means any length, _ means one character, and the entire string must match. A simple Python translator is:

Python
#| eval: false

def sql_like_to_regex(pattern):
    parts = []
    for char in pattern:
        parts.append(".*" if char == "%" else "." if char == "_" else re.escape(char))
    return "^" + "".join(parts) + "$"

fruit = pd.Series(["apple", "banana", "pear", "pineapple"], dtype="string")
fruit.str.match(sql_like_to_regex("app%"), na=False)
fruit.str.match(sql_like_to_regex("ba_ana"), na=False)

A production translator must also honor escape characters. If the data already lives in a database, let that database execute LIKE.

Four pattern engines

R
x <- c("a.b", "axb")

str_detect(x, regex("a.b"))
str_detect(x, fixed("a.b"))
str_detect(c("I", "İ", "i", "ı"),
           coll("i", ignore_case = TRUE, locale = "tr"))
str_split_1("Hello 世界. Next sentence!", boundary("sentence"))

Choose by intent:

  • pattern language: regex();
  • exact byte sequence: fixed();
  • human-language comparison: coll();
  • character, word, line, or sentence boundaries: boundary().

Python re covers regex, and in / str.find() covers literal search. The standard library has no complete equivalent to the last two.

Performance, security, and maintainability

  1. Prefer fixed() or regex=False for literal text. The intent is clearer and it is often faster.
  2. Compile reused Python patterns with re.compile(); avoid rebuilding complex patterns inside loops.
  3. Prefer vectorized work. Avoid ordinary Python functions over each row of a large Series when a Series.str operation exists.
  4. Do not parse HTML, XML, JSON, CSV, or a programming language with regex.
  5. Escape dynamic input with str_escape() / re.escape() and constrain complexity.
  6. Define what missing, empty, whitespace-only, and invalidly encoded values mean before cleaning.
  7. Specify locale for names, sorting, casing, and search, and test the actual target languages.
  8. Give each regex positive, negative, boundary, and missing-value test cases.

Troubleshooting

The number of backslashes is wrong

An R digit pattern is "\\d+". Python should normally use r"\d+". Inspect what the engine receives with writeLines(pattern) or print(repr(pattern)).

Literal input is accidentally treated as regex

Dots, plus signs, parentheses, and brackets are metacharacters. Use fixed(), regex=False, or escaping.

Positions are off by one

stringr str_locate() / str_sub() is one-based and end-inclusive. Python spans and slices are zero-based and end-exclusive.

A pandas mask contains missing values

Use s.str.contains(pattern, na=False) before filtering. Otherwise the mask's dtype and missing-value behavior may be surprising.

str.extract() says there are no capture groups

pandas Series.str.extract() requires parentheses in the pattern. Wrap the complete match in a capture group, or use findall().

A regex works in R but not Python

Check ICU versus re syntax for named groups, Unicode properties, POSIX classes, lookbehind, and replacement backreferences.
